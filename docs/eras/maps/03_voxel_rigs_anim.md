## 1. What the subsystem does today

- **Model** = `ModelDef` (`src/voxel/model.js`, 60 lines): `parts[]` (parent-first, `byId`), `attach{name:{part,at}}`, `meta{}`, `voxelSize` 0.1 u. `addPart(id, VoxelGrid, {parent, origin(voxels, relative to PARENT pivot, stored x0.1), pivot(voxels in own grid), rest[rx,ry,rz], shadow})`. Pose = `T(origin+poseT)*R(pose, Ry*Rx*Rz)*R(rest)*S(poseS)`. Voxel = Uint32: bits24-31 flags `F_SOLID|F_TEAM(2)|F_GLOW(4)` (bits 3-7 free), 0xRRGGBB. Builders are pure and deterministic (`RNG(hashString(bp.id))`, `hash3`); no `Math.random` in any model code.
- **Rig id** lives in `model.meta.rig`; composed models carry `meta.subrigs=[{prefix,rig,parts,kind}]` (`voxel/compose.js composeModels`: item parts get a prefix, root parts hang on a named attach of the base). Animator reads: `rig, subrigs, clipMap, species, weaponStyle, pivotY`; tools read `kind, builder, height, footprint, fallback`.
- **Render**: one `VoxSkin` per `u.def.id` (`'c:'+custom.id` for custom soldiers) created lazily in `BattleView._rec` (capacity 32, doubles on growth): ONE merged geometry (`aPart` attr), a near `InstancedMesh` + a far one (`downsample2`, no shadow), part transforms in a RGBA32F DataTexture (3 texels/part x rows=instances). **`MAX_PARTS = 48`** (`voxskin.js:112`, constructor throws).
- **Animation**: the sim publishes ONE clip id per unit (`u.anim={clip,t,rate,flinch,dir,prev,blend}` + `u.gait`, speed). `Animator.pose(model,state,extra,out)` (pure, `animator.js` 867 lines) crossfades (blend/0.14 s, `x^3(4-3x)`), picks gait mixes from speed, drives feet by distance, derives mount/rider/crew clips, runs hum-only overlays (idle sway, flinch, cape/crest, weapon `aim`, shield counter-rotation), wheel roll, runtime ground-fit for death/getup/sit/sleep/tumble/knockdown. Cost measured: 0.85-2.9 us per `pose` (7-43 parts, walk, Node warm).
- **Clips** = DSL keyframes + `build(c,t,u)` baked at 30 fps (`anim/dsl.js`), plus IK gait generators (`anim/gait.js`), plus 17 adopted retargeted UAL clips (hum1 only, `anim/ual*.js`, `assets/anim/humanoid_clips.json` 340 KB). `ClipLib` (`anim/clips.js`) stores `rig:id`; the PLAIN id (what the sim asks) belongs to hum1 if hum1 has it, else the first registrant; the SIM reads `ClipLib.dur/hit(id[,rig])` for windup/hit/death-linger timing, so **clip timing is simulation input** (`combat.js startMelee/startRanged/killUnit`). `DEFAULT_META` (clips.js) holds the design timing used by Node sims before baking; `tests/anim/clips.test.mjs` forces baked == design (+-25% dur, hit +-0.06/20%, rig variants +-0.1 s).
- **Attack clip contract** (`combat.js`): `rate = clamp(dur/(cd*0.92), 1, 2.4)` (clips are only sped up), release at `hit/rate`. `rangedClip(def)` is hard-wired: `arrow->shoot_bow; boulder|bolt->launch (siege|monster) else throw; sunbeam|scepter|thunderbolt->cast; everything else->throw`. Projectile leaves at `u.pos + sin(heading)*0.5, y + def.height*0.72` (`sim/projectiles.js:36`), NOT at the model's `muzzle`.
- **Humanoids**: `compileSoldier(blueprint)` (`blueprints.js`) is the only path to hum1: 16 canonical parts, a global `PART_REGISTRY` (12 categories, **254 parts**: helms 55, hair 13, faces 15, tunics 22, armors 18, shoulders 12, legs 13, skirts 3, capes 9, backs 14, mains 56, offs 24; 12 locked), 6 metal ramps, 9 emblems. Mains by style: bash 15, overhead 9, thrust 9, slash 7, throw 5, cast 5, shoot(bow) 4, pike 2. 28 of 43 defs are hum1.
- **Non-humanoids**: `beasts/*.js` builders on the `LG/SLG` local-grid toolkit (`common.js`), 15 `BUILDERS`; mounted = `buildMounted` (quad1 + hum1 rider via `composeModels`, rider seated by static `SEAT_REST` rotations, clips only add deltas).
- **Budgets enforced by tests**: parts 5..48, height < 9.0 u, footprint x<6 z<10 u, voxels 250..140000, lowest voxel y in (-0.051, 0.11) (nothing floats), team-tint >= 15% mean and >= 3% per projection (`tests/beasts/builders.test.mjs`); humanoids <= 16 parts, 600-6000 voxels, height 2.4-3.4 u (U2); tint >= 30% pooled (`tools/tintcheck.mjs`).

## 6. RISKS (numbers)
- **Clip timing is simulation input**: any retime/replace of an existing hum1 plain id (or UAL warp) changes Ancient balance and campaign records (O4). Safe path: new ids only, with `DEFAULT_META` rows equal to the baked clip (A-tests: +-25% dur, hit +-0.06 s or 20%; rig variants +-0.1 s). `hum1` always takes the plain slot of an id (`ClipLib.register`): defining `reload`/`launch` on hum1 re-owns ids currently owned by catapult1.
- **Part cap**: 48; biggest shipped 43 (chariot_archer). Full-compiled crew cost 10-13 parts each: crew budget = (48 - rig parts)/10 (3 crew on a 9-part trebuchet = 39, 4 crew = 49). A knight with plume+cape+back+quiver on a barded horse = 27.
- **Triangles**: PF2 budget Marble 120 near + 380 far <= 1.2 M (avg ~5 K near / 1.6 K far); heavy models switch to far earlier (`lodK2`, floor 0.2 = 25 u). Ancient: 10 of 43 defs exceed 15 K near tris. Targets (est): infantry <= 7 K, vehicles <= 22 K, siege <= 30 K, boss <= 55 K (elephant is 55 K / 27.5 K quads = ~11 MB CPU + 5.5 MB GPU per skin: `VoxSkin` keeps `this.geometry` AND a `geometry.clone()` per mesh = ~400 B/quad CPU, 200 B/quad GPU).
- **Draw calls**: <= 2 per live skin (+1 shadow draw per near mesh); TYPE_CAP = 16 types per TEAM (`game.js:33`, placement UI; armygen `MAX_TYPES` 16, default 9) -> up to 32 skins = 64 unit draws + 32 shadow; R2 assumes 12 types / 24 unit draws of 160 total. A Time Warp mix (O1) can exceed it; custom soldiers count as types.
- **Build hitch**: a first frame with many new defs builds them synchronously: Ancient worst case ~350 ms Node (344 ms for all 43), browser similar-or-slower (unmeasured); new eras do not add boot cost except clips. Part texture: 144 x cap x 16 B (48 parts, cap 1024 = 2.4 MB); capacity growth 32->64->...->1024 reallocates texture+geometry clone at each doubling.
- **Boot**: bake+register 92 ms for 146 clips (0.63 ms/clip); +~100-150 new clips (3 eras) = +65-95 ms before the title unless baked per rig lazily; clip data +~0.3-0.5 MB RAM.
- **Page size**: Ancient model code = parts 269 KB + beasts 139 KB + units 23 KB + anim 240 KB + UAL JSON 340 KB raw of a 3.1 MB packed page (budget 5 MB). Three eras at Ancient density (parts + builders + units ~ 430 KB raw each, ~25-30% compressed) = roughly +0.35-0.45 MB packed (est).
- **Silent fallback**: builder exceptions become fallback models with a console.warn, and the gate runs contracts non-strict (seam 15).
- **Determinism**: model builds are pure and hash-stable (tests hash every grid), Animator never feeds the sim; do NOT edit Ancient builders (exact builder-id list asserted in `builders.test.mjs`, hash determinism tests).
- **Save compat**: blueprints are `v:1` JSON of string part ids + paint RLE keyed by canonical part id and size; adding parts/metals/styles is safe, changing `DIM` sizes or removing/renaming a part id breaks saved customs and share codes. `randomBlueprint` output changes when the registry grows (Workshop "randomise" only, not persisted).
- **Far LOD**: single-voxel features vanish (needs 3 of 8 voxels in a 2x2x2 cell): rifle barrels, antennas, spears; keep >= 2x2 cross-sections for anything that must read at distance. Animation LOD: 0 (<38 u), 1 (<61 u, no overlays), 2 (frozen pose), skipped beyond `farDist` 260.
- **Preview/readability**: tint floors (15% non-hum, 30% hum pooled) are hard to meet on camo/metal sci-fi hulls: plan team-tint panels (pennants, stripes, glow trim `F_TEAM`) from the first sketch.

## 7. UNKNOWNS (and how to resolve)
- Browser (V8 + SwiftShader/GPU) cost of `modelFor` + `new VoxSkin` per model type: only Node was measured. Resolve: `tools/perf.mjs`/`smoke.mjs`-style probe with `performance.now()` around `BattleView._rec` for a 16-type army.
- Whether SIM will add a flying layer / `def.ranged.clip|muzzle` / independent turret facing (maps 02/05). Everything in section 5 marked "SIM" depends on it; rendering-only fakes are listed.
- How the era registry (map 01) will namespace unit ids, part ids, builder ids and sheet lists; seams 1, 2, 16, 20 follow its design.
- Whether Workshop (custom soldiers) must offer new-era parts and weapon styles (needs `sim/stats.js` classes for rifle etc. and Workshop UI filter by era) or stay Ancient-only.
- UAL: raw GLBs exist locally (`assets/raw/quaternius-ual1/files`, git-ignored; `tools/anim/mapping_ual.json`); Driving/Sitting clips are one mapping entry away but two-handed gun poses were measured unusable. Whether seated/driver clips are worth a re-bake: look at `docs/anim_spike/` filmstrips.
- Real per-quad memory (the 400 B/quad estimate comes from reading `_buildGeometry`/`_makeMesh`, not from a heap snapshot).
- Exact hum1 clip count after the gun kit and the resulting `humanoid_clips.json`/boot growth: depends on how many gun postures are authored.
- Hover/air units vs the builders test `minY` rule and the roster steps/s test: need explicit exemptions (`meta.hover`, per-id list) decided with QA.
