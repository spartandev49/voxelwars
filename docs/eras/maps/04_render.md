## 1. What the subsystem does today
- 17 files, 2,938 lines, ~185 KB. THREE r128 global (`window.THREE`), one WebGL2 context, one `Engine` (`engine.js`). Every tier renders scene -> half-float MSAA target -> bloom chain -> ACES composite (`post.js`); tiers only change bloom levels, MSAA, pixel ratio, shadow-map size, cloud/weather/particle caps.
- Frame (`app/game.js:590-607`, `Game.frame`): sim ticks (<=5 per frame, `fx.update(0)` after EACH tick) -> `rig.update` -> `view.update(alpha, dt, camera)` -> `fx.update(rdt)` -> markers/weather/zones -> `terrain.update` (<=4 dirty chunks/frame) -> `props.update` -> `engine.render` (sky follows camera, clouds scroll, shadow frustum snaps to texels around `engine.focus`).
- The view reads LIVE sim objects, no snapshot copy: `world.units`, `world.dying`, `world.proj.list`, `world.arena`, `world.defs`, and sync callbacks on `world.events` (payload objects are reused: read, never retain). Interpolation = `alpha` between `px,py,pz,pheading` and current.
- Units: one `VoxSkin` per model key (def id, or `c:<customId>`), created lazily by `BattleView._rec` and NEVER evicted (only `forget(id)` for edited customs). A VoxSkin = near InstancedMesh + far InstancedMesh (half-res part grids, ~27% of the triangles, no shadow) + a depth material; ALL parts of a model are one merged geometry, `aPart` per vertex, per-instance part transforms (3 RGBA32F texels per part) in a DataTexture fetched with `texelFetch` in the vertex shader. CPU does the whole part chain per instance per frame (`VoxSkin.add`).
- Fields the view reads per unit: `id def(id,role,mass,armor,hp) team x y z px py pz heading pheading pitch roll scale radius height speedNow gait hp hpMax state alive vip flash stone custom kx kz se[] anim{clip,t,rate,flinch,dir,prev,blend}`; `se` slots read: 0 BURN,13 POISON,5 SLEEP,3 ROOT,7 RAGE,4 CONFUSE,12 TIPSY,10 CURSE (`battleview.js:21 statusMode`). NOT read: `u.glow` (set by rage), `u.altitude` (dead field), `u.ky`, `u.team` for projectiles. Per projectile: `active kind px py pz x y z vx vy vz id` (`stuck` is not read, so stuck projectiles stay drawn).
- Projectiles: ONE InstancedMesh of lit boxes (cap 1500, `battleview.js:156`), shape from `PROJ_VIS[kind] = [length, thickness, sRGB colour, glow]` (10 kinds, unknown kind = arrow look), oriented along velocity; glow kinds (>0.5) shed a 0.1 glow cube every other frame.
- Everything else is event-driven CubeFX (`fx.js`, one InstancedMesh of opaque lit cubes): hit sparks/gore, kill dust/fire, corpse debris burst (palette sampled from the model), explosions (rubble+fire+smoke+dust scaled by `r`), telegraphs and hazard bursts as rings/cones/lines of cubes laid on the terrain, heal sparkles, lightning arcs. Craters are real heightfield edits: `crater` event -> `terrain.markDirty` -> chunk rebuild (4 per frame).
- Terrain: 32-cell (16 u) chunk meshes (`terrain.js CH=32`, 36 draws medium / 64 large), vertex colours + AO + strata bands from `MATERIALS`, one animated shader plane for water OR lava (`arena.lava` boolean).
- Sky/light: `Engine.setEnvironment(env)` is the only look function: `env.time` (sun path, dusk/night blend), `env.weather` (grey blend), `env.fog`, `env.wind`. `env.theme` and `env.mood` are NOT read by any render code (theme is audio-only: `audio/engine.js:471`, `game.js:445`). Palettes are hard-coded constants (`engine.js:153-154`), fog colour = horizon colour, one sun, stars by night factor, 26 cloud groups by tier.
- Budgets are enforced softly at run time (`BattleView` near budget/LOD, `PropRenderer` draw governor, `CubeFX` cap, `Loop._autoScale`), measured by hand (`tools/perf.mjs`), NOT gated except props (`tests/props/renderer_page.js:32`: <=60 draws, <=60 batches).
- MEASURED (B), Marble, marathon LARGE (256 cells), 570 units, camera framing the whole arena, props updated: **159 draw calls (all passes) of the 160 budget; 1.53 M triangles**. Split via the probe's hide-group deltas: terrain 97 calls/0.24 M tris, props 39/0.19 M, unit skins ~10 calls/1.07 M tris, shadow pass 77 calls/0.44 M, rest (sky, clouds, fx, bars, rings, projectiles, post 8) ~13. Browser sim tick 6.6 ms and `view.update` 8.2 ms (361 drawn) on a shared SwiftShader box; JS heap 177 MB with 18 skins held. The shipped `tools/perf.mjs` never calls `props.update`, so it reports 145 calls/1.48 M (props invisible): QA2's "132 calls" understates the real total.

### 2.2 CubeFX API (`fx.js`)
`new CubeFX(scene, arena, cap)`, `setCap(n)`, `setArena(a)`, `clear()`, `update(dt)` (compacts live entries to the front; `update(0)` is legal), `liveCount`. `spawn(x,y,z,vx,vy,vz,rgb,size,life,{g=22,drag=0.2,bounce=0.3,grow=0,spin=rand,flags})` with flags 1 = settle on ground and linger (debris), 2 = glow (colour x1.6, bloom), 4 = shrink-only, 8 = internal "settled". Cubes are UNIFORM (one size), opaque, Lambert-lit, no alpha, no per-particle light, no children. When full the oldest SLOT is overwritten (ring). Recipes: `sparks dust smoke fire splat(style red|wine|confetti|off) confetti debrisBurst rubble lightning`. Gravity constant 22 (= sim `G.gravity`). Cost (N, stub THREE): `update` 0.79 ms at 11,500 live, 1.72 ms at 23,000.

### 2.3 VoxSkin shader and data interface (`voxskin.js`)
| slot | content | spare? |
|---|---|---|
| vertex attrs | `position normal color` (AO-baked linear), `aFlag` (0 plain, 1 team-tint, 2 glow; from voxel flag bits `F_TEAM=2`, `F_GLOW=4`), `aPart` | voxel flag bits 8..128 are unused; `aFlag` values >=3 would be read as glow today (`aFlag > 1.5`) |
| instance attrs | `instanceMatrix` (root yaw/pitch/roll + scale + position), `instanceColor` (team rgb, multiplied into aFlag==1 voxels), `aFx` vec4 | attribute locations used: 11 of >=16 (WebGL2 minimum) |
| `aFx.x` | hit flash 0..1 (warm orange pulse) | used |
| `aFx.y` | stone 0..1 (desaturate; sim `u.stone` ramps up under `SE.STONE`) | used; could share |
| `aFx.z` | `glow + 4*statusMode` (mode 0 none,1 burn,2 poison,3 frozen/root,4 sleep,5 rage,6 tipsy/confuse,7 cursed; shader treats anything >=6.5 as cursed) | modes 8+ need a shader branch |
| `aFx.w` | texture ROW of this instance (near and far share one texture). `docs/spec.md` section 9 says "reserved, always 0": STALE, the code is truth | used |
| `uPartTex` | RGBA32F, width `3*P`, height = capacity; texel k of part p = row k of the 3x4 affine [m_k0 m_k1 m_k2 t_k] | all 4 channels used; one extra texel per row (width `3P+1`) or a 4th texel per part would be the lane |
| uniforms | only `uPartTex` (+ three fog/lights). NO time uniform | add a shared `uTime` object |
| varyings / key | `vFx`, `vGlow`; `customProgramCacheKey 'voxskin-lambert-v1'` (depth: `voxskin-depth-v1`) | bump the key on any shader edit |
Materials are opaque `MeshLambertMaterial` (per-VERTEX lit in r128, verified `vLightFront` in the bundled build). Units never receive shadows (`receiveShadow=false`); near mesh casts via `customDepthMaterial`. `skin.add(x,y,z,h,sx,sy,sz,pose,team,flash,stone,glow,pitch,roll,lod)` has 15 positional args (defaults for the last 6); returns the instance row `i`; `attachWorld(i, partIdx, lx,ly,lz,out)` gives a world point on a part (unused by the game today: BattleView drops `i`).

## 6. RISKS (numbers)
- **Draw calls: 159 of 160 now** (B, Marble, large arena framed whole). Terrain alone is 97 (64 chunks in the main pass + the chunks inside the shadow frustum). New layers cost +4..5 (streaks, shields, blobs, hazards) and more unit types add 2 each (near+far; +1 shadow). Budget must be bought back before content lands: (a) coarser terrain chunks beyond ~60 u (64-cell super-chunks: 97 -> ~45), (b) merge markers (3 per marker now, 8 max = 24), (c) lower `DRAW_BUDGET` 52 only if props stay <= 39. The shadow pass is 77 calls/0.44 M tris and is counted in `engine.stats` (all passes accumulate, `engine.js:48`).
- **Triangles: units are 70%** (1.07 of 1.53 M at 570 units). Per-model near/far tris (N, 43 Ancient defs): humanoids 3.6-6.9 K (median 4.8 K) / 1.1-1.9 K; cavalry 15-18 K; catapult 26.1 K; ballista 26.9 K; cataphract 26.4 K; chariot_archer 32.1 K (43 parts); trojan_horse 34.0 K; war_elephant 55.0 K / 14.2 K (36 parts, 56 K voxels). Mean 10.5 K / 2.8 K. A tank (50x16x22 voxels hull + turret + barrel) is ~14-18 K at voxelSize 0.1 (N estimate: 4.5 K quads for the box shell alone = 9 K tris); a mech 2x humanoid height = ~4x the faces = ~19 K. The PF2 reference is 1.2 M at 500 units (already exceeded beyond ~300 units; 600-unit probe read 1.17 M after the near budget cut to 110). Tier proposal if triangle-based: near-triangle budget about 1.0 M (Marble), 0.4 M (Papyrus), 0.15 M (Potato), 2.5 M (Olympian).
- **CPU**: `view.update` 6.0-8.2 ms at 570 hum1-class units (B); `skin.add` is linear in parts (6 trig per part). A 600-unit modern army at 30-40 parts/unit is ~2.5x the part count: ~15-20 ms unless seam 13 lands. The animator adds its own cost (anim map). Mesh+model build at first sight of a type: 25-110 ms cold (N), no prewarm for views: hitches on wave reinforcements of a new type. `fx.update(0)` per tick: seam 27.
- **Memory**: ~300 B per triangle per skin (2 CPU copies + GPU) and no eviction: 43 Ancient types fully visited = ~170 MB (N estimate); three more eras (~110 types, bigger) could reach 0.5 GB in one long session; measured 15-min mixed session heap 284 -> 399 MB (QA2). Texture upload per frame = `P*3*capacity*16 B` per active skin: 0.7 MB/frame at 570 hum units (B), ~0.9 MB per heavy type at capacity 512 (full re-upload; r128 DataTexture has no partial update); `_grow()` doubles capacity (32 -> 512 = 4 re-allocations and geometry clones per type per battle): pre-size from `world.stats` counts.
- **FX pool**: shared ring; one big barrage evicts settled debris and trails (cap is debris+particles = one pool). Marble 11,500 cubes x 0.79 ms. Settling debris lives 8-14 s.
- **Terrain rebuild**: 3.1 ms per chunk (N); `flush(4)` = up to 12 ms in one frame under artillery; nav/minimap rebuild lag behind (sim#20, `game.js:674` 1.2 s).
- **Shader/program count**: any new define, uniform or key change recompiles; `Engine.setQuality` marks every material `needsUpdate`; point-light count must stay constant (pool of 2 in props) or every Lambert program recompiles; attribute locations 11 -> 12 with `aFx2` (limit >=16); varyings to be checked on the target GPUs.
- **Determinism**: view code uses `fxRand` (seeded from `Math.random`) and its own LCGs; it never touches `world.rng`; keep it that way (a replay/balance run that ignores render must stay byte-identical). `statusMode` and event payloads are read-only. The Ancient look must stay pixel-identical: default theme path = current constants.
- **Save compatibility**: render owns no saved data. Touch points: arena JSON `env.theme` (free string <=16, already persisted), `MATERIALS` ids (frozen, append only: world#5), settings `quality` ids and tier labels (Papyrus/Marble/Olympian are Ancient-flavoured UI strings; keep ids).
- **Pause leak**: glow-trail spawns run on `view.time`, which advances while the sim is paused (`fx.update(0)` while paused), so rockets frozen mid-air keep spawning cubes into the ring.
- **Readability**: team colour only tints voxels flagged `F_TEAM`; grey vehicles or cloaked units need explicit team voxels (`tests/units/tint.test.mjs` pattern) and the CVD palettes must stay legible under neon/lunar grades (R14).
