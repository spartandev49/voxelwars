# Map 05: world, arenas, terrain, materials, props, nav, Arena Builder (cartographer output, read-only survey)

Measured on the working tree at 2026-10-08 with `node` scripts (scratchpad only, nothing in the repo changed except this file). "BLAST" = files that must change. Owners: `src/world` COORD, `src/sim` SIM (requests only), `props/catalog.js` SIM, `props/models/*` PROPS, `src/editors/arena` EDITORS-A, `src/render` RENDER.
Naming trap: `src/content/era_ancient/blueprints.js` is the SOLDIER blueprint compiler (humanoid ModelDef), NOT arena blueprints. An "arena blueprint" is three things: (a) the `Arena` data object (`world/arena.js`), (b) a generator recipe (`R.<id>` in `world/gen.js`), (c) a preset row (`era_ancient/arenas.js ARENAS`).

## 1. What this subsystem does today
- An arena is a pure-data heightfield (`Arena`, world/arena.js, 189 lines): `size` cells per side (128/192/256 = 64/96/128 u; fromJSON also accepts 64,96,160,224), CELL = HSTEP = 0.5 u, `h` Uint8Array (height steps, MAX_H 120 = 60 u), `m` Uint8Array (material id, 16 defined), one global `water` plane (steps, 0 = none) with `lava` boolean, `props[{t,x,z,r,s,v}]` (<= 1500), `zones{A,B}` (two axis-aligned rects, x,z centre,w,d), `hazards[{t,x,z,r}]` (<= 60), `markers[{id,type,x,z,r}]` (<= 8), `env{time 0-24, weather, fog 0-1, theme, wind 0-1, mood}`, `biome` (free string), `objective` (5 ids), `tags` (<= 5), name/author/desc/seed. `clone()` = `fromJSON(JSON.parse(JSON.stringify(toJSON())))`, and `World` clones its arena, so any field not in toJSON/fromJSON is LOST in battle.
- Terrain is generated by recipes (`world/gen.js`, 828 lines / 61 KB): `generateArena(recipe,size,seed)` builds `new Gen(arena, RNG(seed*7919+13), Noise2D(seed+101))` then runs `R[recipe](g)`. Gen holds a float height field F and material field M: `fill(hfn,mfn)`, `smooth`, `flatZone(s)`, `flatRect`, `terrace`, `commit` (despike + island merge), `paint`, `slopeMat`, `levelDisc/levelStrip`, symmetry `g.sym` = rot|mx|mxz (`S(f)` symmetric noise, `_copies` mirrored props), and a prop placer: `put` (checks bounds, lava, water, zones, keep-clear lanes, hazards, slope, spacing), `scatter`, `groves`, `line`, `ring`, `raw` (no checks), `keepClear/keepClearPath`. Prop counts scale with area (`areaK = (W/96)^2`). Deterministic, no Math.random.
- Walkability: `NavGrid` (world/nav.js, 221 lines): 1 u cells (n = size/2: 64/96/128 per side), a cell is walkable when its 2x2 terrain block spans <= 3 steps (1.5 u), is not deep water (> 0.8 u below plane), not lava plane, not lava material; neighbour steps need mean-height diff <= 1.0 u; cost = 1/material speed (x1.7 in shallow water). `applyProps` stamps `block` (indestructible blocking props) and `soft` (blocking props with finite hp) with circle radius r+0.35; soft cells are solid for movement but passable for pathing (+30 cost); hazard cells +8. `FlowField` = bucket Dijkstra, two per world (one per team). No unit-radius clearance, no air/hover classes: movement tests the unit centre cell only.
- Props: catalog record (`era_ancient/props/catalog.js`, 52 lines, 41 ids) `{cat,name,r,h,hp,blocks,cover,flam,place,scale[min,max]}` + a procedural model builder per id (`props/models/*`, 7 files 1,635 lines / 107 KB). Sim `Prop` (sim/world.js:32): radius = r*s, height = h*s, hpMax = hp*s. Behaviour is derived from fields only (no "type" switch): blocks+finite hp = soft/destructible, blocks+Infinity = hard, `cover` stops projectiles below height h (`World.propBlocks`, binary, no partial cover), `flam` burns (18 hp/s, spreads via `igniteAt`).
- Destruction: `hurtProp` -> `prop_damaged{hpFrac}` (stage 1 under 60%) -> hp <= 0: `dead=true`, `prop_destroyed`, `_indexProps`, `nav.applyProps`, `invalidateFields`. Dead props block nothing (spec says rubble is "half radius" but the code removes the footprint entirely; rubble is visual only). Terrain can be deformed in battle only by `World.makeCrater` (-> `arena.crater`, `nav.rebuild(rect)`, `crater` event -> TerrainRenderer.markDirty + PropRenderer.reground).
- Render: `TerrainRenderer` (render/terrain.js, 164 lines) meshes 32-cell chunks via `terrainMesh.js` (top quad per cell with AO, strata bands; 36/64 chunks on medium/large = 36-64 draws, 90-170k tris, ~100 ms to mesh in Node) plus one shader water/lava plane. `PropRenderer` (render/props.js, 614 lines): one `Batch` per (type,stage,variant) with up to 3 LOD InstancedMeshes, frustum + distance cull, `DRAW_BUDGET = 52` governor that only merges LOD1 into LOD2.
- Arena Builder (`src/editors/arena/*`, 18 files, ~3,480 lines, 16 tools) edits an `Arena` through `EditSession`; exports/imports `VW1.arena.<deflate+b64url>.<crc32>`; library = `vw.arenas` Collection (cap 48) of `{id,name,author,desc,tags,size,updated,objective,thumb,code}`; draft `vw.draft.arena` every 20 s.

### 2.5 Prop model format and cost
Spec = `{variants 1-4, indestructible?, pal:[<=12 debris colours], build(v,rng)->Pen, damage?(pen,rng,v), rubble?:{w,d,h,cols,kind 'chunks|planks|leaf|mixed',n}|fn, afterRubble?}` registered in a module's `MODELS`; `makeBuilder` (kit.js:266) -> `build(stage,variant,rng)` -> `ModelDef(id, 0.1)` with one part `root`, pivot = footprint centre at ground, front +Z, buried foundation skirt (`Pen.ground`), `meta {kind:'prop',rig:'static',ground,type,stage,variant,indestructible,emitters[]}`. Voxel value = `V(rgb, flags)`; `F_GLOW` (G()) glows with bloom; `Pen` API: box, fill(fn), blob, frustum, disc, tube, emit('fire'|'smoke'|'ember'). Stage 1 = same build + `defaultDamage` (chip/cracks/darken/prune); stage 2 = `rubblePile` (<= 2.2 u mound). Deterministic (`propRng` = hash(type) ^ variant).
Cost (41 props, variant 0, stage 0): 1,984,831 voxels total, median 3,449, p90 50,968, max pyramid 986,215 (grid 141x128x141 = 9.7 MB Uint32 transient), temple 593,599 (4.3 MB). Build 215 ms for all 41 (1,183 ms for all 4 variants x 3 stages = 483 models), lazily per (type,stage,variant) and cached in `GEO` (props.js) until `disposePropGeometry`. Meshes: LOD count by voxels (<2,400: 1, <9,000: 2, else 3; each LOD = `downsample2`, voxel size x2). LOD0 tris: bush 2,980, crate 1,200, tree_oak 14,348, wall_stone 7,216, tower 29,948, arch_gate 37,280, statue_zeus 29,188, ship 20,428, pyramid 159,088, temple 239,812. Per frame cost is instancing: 1 draw per visible (batch x LOD). Draw math per arena (type,variant) batches / LOD meshes: marathon 22/39, colosseum 15/23, nile 32/46, giza 34/54, carthage 33/61, teutoburg 36/61 (984 props), troy 45/84 (> DRAW_BUDGET 52, governor merges mid LODs), styx 18/20. Source cost: ~2.6 KB per prop model (107 KB / 41), catalog ~100 B/prop.
Terrain (all arenas): 36 (medium) / 64 (large) chunk draws, 90-170k tris. R2 target: <= 160 total draws at Marble (measured 123-132 with units).

## 6. RISKS (numbers)
- Ancient layout drift: recipes are deterministic and campaign/puzzles hard-code marker coordinates for them (e.g. `pharaoh_start x47 z4`, `goat_start -24,-22`). Any change to Gen core (RNG call order in `put/scatter/groves/pickVariant`, `ok()` rules, commit/despike) shifts props/terrain, breaks markers, S22 fairness bands and "campaign records" (request O4). There is NO golden test today (tests only compare two runs). Golden FNV-1a-32 of `JSON.stringify(generateArena(recipe,size,seed).toJSON())` at preset defaults, measured today and stable across runs: marathon 69180a92, thermopylae 67e1ad1b, colosseum 6f4c0945, nile 96a91af5, giza 14bd8981, persepolis 4bea79f7, carthage 1b9deb14, teutoburg cefe23ae, alpine c0bce31a, olympus d44f87ad, troy e8837ad3, styx 279dc860, cyclops 5e3c83c5, oasis ec4f0881, arenalab 9e6da655, random 6ac53394. Commit these as `tests/gen.golden.test.mjs` BEFORE any gen.js split. `random` picks from a fixed 8-recipe list by `rng.int(0,7)`: adding picks changes it, so era randoms need their own recipes.
- Determinism: world/ and content/ lint forbid window/THREE; content/ and sim/ forbid Math.random (tools/lint.mjs). New recipes must use only `g.rng`/`g.nz`. `Arena.clone` via JSON means float rounding in toJSON (`toFixed(2)` x,z; 3 r; 2 s) is applied before the sim sees props: placement precision is 0.01 u.
- Draw calls: draws = visible (type,stage,variant) batches x used LODs; the governor can only fold LOD1 into LOD2 (batches with 3 LODs), never reduce batches. Troy already has 45 batches / 84 LOD meshes. A city/jungle with 30 types x 3-4 variants plus damage-stage batches (stage 1 and 2 are separate batches) can pass 100 visible batches; total budget is 160 (terrain 36-64 + props + unit skins <= 24 + fx/weather/water ~10; measured 123-132). Rule for recipes: <= ~35 visible (type,variant) pairs, cap variants per type per arena (2), share rubble. Triangles: Teutoburg alone is 10.0M LOD0 tris if everything were near (984 props); LOD + cull handle it, but big-model era props (tower 30k, hangar-class 100k+) multiply.
- Prop memory/build time: a 0.1-voxel building 30 x 20 x 12 u = 300x200x120 = 7.2M cells = 29 MB Uint32 transient and > 150 ms to build (pyramid 986k voxels = 18 ms build, 9.7 MB grid). Use `voxel` 0.2-0.25 for anything > ~10 u (cells fall 8x-15x) and cap each model at ~100k voxels; whole Ancient set builds in 215 ms.
- Nav/sim cost: `applyProps` 0.08 ms for 984 props, `nav.rebuild` full large 0.71 ms, FlowField.compute 1.1 ms (medium, 9,216 cells) / 2.9 ms (large, 16,384). Each prop death re-stamps all props, allocates `props.map(navProp)` and invalidates both flow fields (`_fieldAll`): sustained artillery in a 1,000-prop city could cost 2 x 3 ms per tick (sim budget: 300 units <= 2 ms per tick). Mitigate by coalescing prop deaths per tick and caching `navProp` objects (SIM).
- Flow-field/AI vs wide vehicles: centre-point nav means a 1.6 u-radius tank squeezes through 1 u gaps and visually intersects props; streets/gates narrower than ~2 x radius + 1 u will look wrong. Elephant r1.5 already exists; Thermopylae gap 8 u, Troy gate lane 8.8 u are fine.
- Share-code size: Teutoburg large (984 props) = 32,726 chars (limit 38,000); terrain-only large procedural = 16,759 chars, +16.2 chars per prop => file-only above ~1,300 props on a noisy large map (city regular grids compress well: 2-material grid + 1,500 props = 12,223 chars). Medium maps 5.8-6.9k. Library: 48 arenas x ~33k chars worst case = 1.6 MB of the ~5 MB localStorage shared with saves; `Collection.put` silently evicts the oldest when over cap 48 (shared by 4 eras).
- Save compat: safe if (a) material ids 0-15 and the 41 prop ids never change, (b) `fromJSON` stays tolerant, (c) new arena fields are optional and omitted from toJSON when default (keeps Ancient codes byte-identical), (d) tombstones added instead of deleting ids. A code from the new build opened in an old build: unknown props rejected, material bytes >= 16 clamped to 15 by `unrle` (silent). Uncounted: `ARENA_IDS` / `ARENA_SET` freeze means new arena plays are not recorded in `arenasPlayed`.
- Look gate: every new arena needs the 3-camera screenshot review and the S22 mirror-fairness run (n >= 400 per arena; symmetric recipes need `g.sym`; asymmetric ones go on the exemption list in spec section 13 with 35-65% band). ~33 new arenas multiplies QA volume 3x.
- Doc/code drift to fix in specs: world.md says stage-2 rubble is half radius and non-cover (code: dead = no blocking at all); editors.md says "40 of the 41"; `LIMITS.propTypes = 41` is a hard error (`prop_types_limit`) once the catalog grows.
- Draw order/render: water/lava plane colours and fog uniform are fixed per `_buildLiquid`; `setFog` only retints; moving to multiple liquids is not possible with a single plane.
