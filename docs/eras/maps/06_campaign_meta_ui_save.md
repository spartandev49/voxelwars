# 06 Campaign, meta-game, UI screens, save: subsystem map (read-only cartographer, 2026-10-08)
Method: every listed file read; counts from `node` imports of the pure modules. "Ancient" = the only era today. Line numbers are as of this working tree. Verdict in one line: the campaign DATA is clean and data-driven, but `campaignApi`, `MISSIONS`, `PUZZLES`, `STAT_TABLE` costs, `MISSION_ORDER`, `MISSION_IDS`, `ARENA_IDS`, `ACTS`, the Mediterranean map and ~30 UI strings are module singletons or literals, and `meta.recordCampaign` will silently refuse to save stars for any mission id not in the Ancient list.

## 1. What it does today (facts)
1. Campaign = 9 missions (3 acts x 3) as pure data: `era_ancient/campaign.js` (287 l, `RAW` array 46-182) + copy by mission id in `campaign_text.js` (212 l) + runtime in `campaign_run.js` (386 l) + validator `campaign_validate.js` (85 l). `build(raw,i)` (campaign.js:185) merges text onto data and adds `index,title,blurb,briefing,victory,defeat,stars[{id,text,test}],objective.text,rewards.{title,blurb,partNames},units{A,B},enemyCost,textId`.
2. Boot wiring: `tools/gen-registry.mjs` OPTIONAL map hard-codes `src/content/era_ancient/{campaign,survival,puzzles,daily,custom,blueprints}.js`, `humor/{announcer,ui_text}.js` into `src/_generated/registry.optional.js` (CAMPAIGN, SURVIVAL, PUZZLES, DAILY, UI_TEXT, ANNOUNCER). `main.js:44-52` copies them onto `content`: `content.campaign = CAMPAIGN.CAMPAIGN`, `.campaignApi`, `.puzzles`, `.puzzleApi`, `.survival` (whole namespace), `.daily` (whole namespace). `buildContent()` (content.js, 79 l) returns `campaign:{missions:[]}` as a placeholder and takes factions/arenas/props/mutators/humor straight from `era_ancient`.
3. Deploy: pin -> overlay `briefing{mission}` -> Deploy builds `game.newSetup('campaign',{mission, arena{presetId:recipe,size,seed,env}, rules{budget}, armies{A.faction=playerFaction, B.faction=enemy.faction}})` -> `Game.begin` -> `modes.resolveMode` (campaignApi.missionById, sets `mode.locked`) + `applyModeRules` (campaignApi.rules = `missionRules`, mutators forced []) -> arena by `campaignApi.arena` (`generateArena(recipe,size,seed)` + env + markers (slice 8) + decor props) -> `new World` -> `campaignApi.setup` = `setupMission`: enemy `enemyForces` -> `world.addPlacements(1)`, `playerFixed` VIP squads, `u.general=true` on listed generals, `new MissionRuntime` chained onto `world.onTick`.
4. The enemy is never placed by the player (`mode.locked`; autoFill(1) refuses). The mission `roster` is NOT enforced in campaign: briefing.js:79-84 passes only faction+budget; only puzzles pass `armies.A.roster` (placement.js:27). `core` is also unenforced (validator + bots only). The palette is just the faction tabs + budget + 16-type cap (`TYPE_CAP`, game.js:33).
5. End of battle (`meta.js` `_finish` -> `buildResults` -> `recordMission` line 535): `capi.summaryOf` (= `battleSummary` + `tracker.extras()`) -> `evaluateStars` -> `M.recordCampaign` (writes `progress.stars[id]` = max, then lifetime stats + 'campaign' achievements) -> unlock parts into `progress.unlocks` AND `progress.parts` -> `out.canNext` via `capi.missions[m.index+1]`. Puzzles: `progress.puzzles[id]={stars,spent,time}` + `progress.stars[id]` (same flat map as missions).
6. Three stars (`evaluateStars`, campaign.js:229): only for a WON non-draw battle of that mission: star1 = win; star2 = `aliveCost(summary.aliveDefs)/playerCostStart >= 0.5` (cost via the ancient `STAT_TABLE`); star3 = mission `starTests[2](summary, mission)`; stars = count earned. Tests in `T` (campaign.js:34-43): thrift, noSpartanLost, quick, goatUntouched, elephantAlive, gateFast, noFriendlyFire, heroesAlive. Puzzle stars: win / spent<=par / bonus (puzzles.js:106).
7. Unlock rule: mission i opens with >=1 star on mission i-1 (campaign.js:265, hud/_progress.js:isUnlocked); first is open. Puzzles are all open. Mutators (9) unlock by TOTAL stars, thresholds `MUTATOR_STARS` 3,6,...,27 (duplicated in campaign.js:17 and content.js:16); computed live, `progress.unlockedMutators` and `progress.titles` exist in the schema but are NEVER written (verified by grep).
8. Map screen: `campaign.js` (138 l) draws an SVG built at runtime by `_map.js` (156 l): 10 land polygons (Mediterranean), 9 recolour ZONES, a Nile polyline, rasterised to a 100x63 grid of 1.6-unit cubes (4,390 land cells), merged to one `<path>` per colour, + clouds/boats/pyramid triangles; pins are absolutely-positioned `<button class="bs-pin">` at `PINS[i]` (map units 160x100) projected into `VIEWS.wide|tall`; route legs are Q-curves between consecutive pins; legend of acts (hard-coded names); phones get a mission list.
9. Codex `locked[]` is read by codex.js but nothing ever writes it (the "Codex: X" reward chips on Results are cosmetic; nothing is gated). `mission.mood` has no consumer outside data/tests (audio picks the track by arena theme).
10. UI strings: `ui/strings.js` `T` (384 l, 38.7 KB) is the menu-side default set (title, quick, placement, settings, credits, codex, ach, stats...). It is overlaid at import time by `humor/ui_text.js` (233 l, 14.7 KB) through `overlayHumor(T,H)`; `getT(ctx)` additionally deep-merges `ctx.content.humor.ui` (unset today). Battle-side screens (campaign, briefing, results, survival, daily) use LOCAL string literals; only puzzles.js uses the override hook `getTB(ctx,'puzzles',TX)` = `ctx.content.humor.uiBattle.puzzles` (unset today). Title roadmap joke: `ui_text.js:79 ROADMAP_TAG` -> `strings.js:313` -> chip in `title.js:61-64` (`vw-title__roadmap`, screens.css:53).

### 2a. Mission schema (RAW, every field; consumer in brackets)
`id` (snake; key of CAMPAIGN_TEXT, MISSION_ORDER, progress.stars, announcer `campaign_<id>`); `unitsA` (briefing "~N units", display); `act` 1..3; `mood` (no consumer);
`arena{recipe in RECIPES, size small|medium|large, seed, env{weather,time..}, markers[<=8]{id,type hill|exit|vip_start|general_spawn|waypoint,x,z,r 1..30, |x|,|z|<=size*0.25}, props[]{t,x,z,r,s,v}}`;
`playerFaction` (id|'mixed'), `roster` (unit ids|null; validated, bots only), `budget` 500..40000, `par` (display + thrift test), `core[{defId,n}]` (validator+bots), `fixed[{defId,marker|x,z,vip,heading,name,def{override}}]` (free player units, the VIP), `reference[{defId,n,order?}]` (authored army: 85-100% of budget, <=16 types, feeds the "Suggested army" button + `counter` bot), `bots{greedy,counter,turtle:[lo,hi]}`+`botsWhy` (defaults .25-.7 / .6-1 / .1-.6);
`enemy{faction, style, difficulty, special, generals[defIds], groups[{defId,n,at{x,z}|{u,v},order advance|hold,squad,formation,spread,dx,dz}], placements[] (puzzles only)}`;
`objective{type in 6, params, markerIds, binding}`, `timeLimit` s (>0), `friendlyFire`, `godPowers` (default true), `morale` (read by missionRules; never set), `teaching` (bool; mission 1 only), `rules[]` (briefing bullets), `starTests[3]` = [null,null,fn], `rewards{unlockMutators[],unlockParts[],codex[]}`,
`script{ waves{placed,firstAfter|first,interval,breather,list[{name?,groups[],after?}]}, vipMarch{to,delay,clear,patience}, zeus{first,every,dmg,r,delay} }`.
Per-mission text (CAMPAIGN_TEXT[id]): `title, act, blurb, briefing[3-5 of {who:brutus|plato|cassandra,text}], victory, defeat, stars[3]{id,text}, reward{title,blurb}`.
### 2b. Puzzle schema
`{id,title,blurb,hint,goalText, arena{recipe,size,seed,env,markers}, player{faction,roster[],budget}, par (<budget), enemy{faction,placements[{defId,x,z,heading,order,squadId,formation}],generals?}, goal{type,params,markerIds,binding?}, timeLimit, godPowers (false x6), fixed[], script, bonus{id,text,test}}` -> built adds `kind:'puzzle',index,stars[win,par,bonus],budget,solution{placements,..}`. Replayed by tests/campaign/puzzles.test.mjs and tools/modes.mjs; `puzzleAsMission(p)` feeds the mission runtime (act 0).
### 2c. Survival / Daily configs
Survival: `SURVIVAL={start 6000,every 40,bonusBase 1600,bonusPer 240,bossEvery 5,enemyBase 2400,enemyPer 900,topN 5,cap 300}`; formulas also live in `sim/waves.js` (2400+900n, 1600+240n, boss every 5th from `BOSS_CYCLE`), names in `era_ancient/wave_names.js` (20 + 5 boss names, imported by the sim); UI keeps a 5-key copy (survival.js:14). Rules: `waves{faction,interval,autoAdvance}`, objective `survive_waves{waves:1e9}`, timeLimit 0. Enemy faction is `'mixed'` = pool of EVERY non-custom def with cost>0 (armygen.js:285-292). Board `{best,bestWave,board[<=5]{score,waves,date,arena}}` in `vw.survival`.
Daily: `dailyPlan(key,content)` = `{date,seed=YYYYMMDD,arenaId,arenaName,size,arenaSeed=(seed%1e5)+1,factionA,factionB,enemyStyle(6),budget 3000,difficulty,mutator|null(67%)}`; mulberry32 draw ORDER: arena index, factionA, factionB (+reroll), style, twist coin, twist index. Two copies of the algorithm: `daily.js` and `ui/screens/_daily_plan.js` (hard-coded 7 `FACTION_IDS` fallback), parity-tested over 400 dates.
### 2d. Runtime scripting (campaign_run.js)
`ScriptedWaves extends sim/WaveSystem` (l.137): `list` waves ARRIVE with explicit groups at zone B via `layoutGroups`; `placed:true` = wave 1 is the hand-deployed `enemy.groups`; gap `after||interval`; a wave is beaten when no enemy is alive and not in `ST.ROUT`; `pending` keeps the objective from ending on an empty field. `MissionRuntime` (l.276): installs on `world.onTick`; `_guardElimination` defines `obj.blocksElimination` (waves pending | `binding` | survive_waves); `_start` arms the VIP march (`routeTo` = Dijkstra FlowField legs, hold until `clear` distance free or `patience`); `ZeusStrikes` (l.181) = telegraph kind 'zeus' + `lightning_arc` + `god_power` events + `w.lightning(x,z,dmg,r)`. VIPs = `fixed[].vip` -> `unit.vip`; generals = `enemy.generals` -> `u.general` (sim `KillGeneral` sets guard/hold); gates/bosses are data: `destroy{props:[{type,count}],eliminate}` over prop TYPES, boss/general = a unit in `enemy.groups`. `MissionTracker` (l.213) counts from sim events: start/lost defs, heroesLost, friendly hits/kills, killsByDef/Cause, `kick` casts, `trample` by war_elephant, 'stone' status, propDownT (time of each destroyed prop type), enemyDownT, vipDamage. `battleSummary` hard-codes `cyclopsMisses:0,maxMeteorKills:0,trojanRevealed:false,wineRain:false`.

### 4a. Save: how to make progress per era WITHOUT touching the Ancient save
Recommended (additive, no version bump): mission and puzzle ids are already global strings, `progress.stars` is already a flat id map, and `totalStars(ctx, missions)` / `isUnlocked(ctx, missions, i)` already take an explicit list, so per-era totals are `filter by era list`. Rules: (a) new eras use unique prefixed ids (`med_*`, `mod_*`, `sf_*`; puzzles too); Ancient ids never change. (b) `progress.unlocks`/`parts` stay flat (keys unique per era). (c) add optional `progress.eras = {medieval:{opened:true,last:'<missionId>'}}` and `progress.lastEra`; `Doc._load` fills missing top-level keys from `PROGRESS_DEFAULTS`, `validateProgress` gets two shape lines; `sanitize` already keeps extra keys. (d) `survival.eras = {id:{best,bestWave,board[5]}}` additive (root stays Ancient, so the `survivalBest` alias and the title tile keep working); `daily` stays single (era is a field of each history row). (e) `stats.campaign.stars` stays flat (extend id gate, seam 19). Result: v2 blobs, v1 blobs (migrate chain), exports, imports and Ancient stars load byte-identical; an old build reading new data simply ignores the extra keys.
Alternative (the explicit form): `progress.byEra = {ancient:{stars,puzzles,unlocks}, medieval:{..}}` with `CURRENT.progress=3`, `MIGRATIONS.progress[2] = d => ({...d, byEra:{ancient:{stars:d.stars||{}, puzzles:d.puzzles||{}, unlocks:d.unlocks||[]}}})`, keep root `stars` mirrored for one release. Costs: every reader changes (`_progress.js starsMap/totalStars`, `_shared.totalStars`, `title.js`, `puzzles.js`, `meta.js` x4, `drafts.js`, `tools/modes.mjs`, 5 save tests + fixtures), and a v3 save is READ-ONLY (`Doc.status='readonly'`) / rejected on import ("saved by a newer version") in any v2 build. Choose it only if per-era resets (e.g. "reset Medieval") are wanted.
