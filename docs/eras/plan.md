# plan.md v2: Medieval, Modern and Sci-Fi eras for VOXELWARS (COORD, 2026-10-08)

Supersedes v1 after the round-1 Socratic review (`q1_scope.md`, `q1_engine.md`, `q1_product.md`, `q1_verify.md`, `q1_content.md`: about 190 questions, 27 blockers; every one is answered in `q1_disposition.md`). Inputs: `e.md` (what the user expects), `maps/01..08` (what the code is). Where this plan and a map disagree, the code is the truth.

This is the master plan: principles, scope, architecture, work breakdown, schedule, policies, verification, decisions. Anything that needs a table of a hundred rows (rosters, mission tables, sim module specs, layer audit, sound bible) is a named **spec deliverable** with an owner and an acceptance script (section 14), written before the build starts.

## 0. Non-negotiables

1. **Ancient does not change**, and we can prove it: ids, stats, layouts, text, sounds, pixels, screens, saves. Proof = goldens G1..G10 recorded from a tagged, hash-verified copy of the shipped build BEFORE the first engine edit (section 3). Changes that necessarily alter Ancient are listed up front in the Ancient-policy table (spec A1) and re-recorded under two signatures; nothing else may.
2. **One engine, data-driven eras.** An era is a pack in `src/content/era_<id>/`, registered and merged; no `if (era === ...)` in engine code. Mechanics are generic primitives reachable from data, inert for defs that do not use them.
3. **Determinism.** 30 Hz sim, one seeded RNG. New randomness only from a second stream `rng2 = rng.fork('era')` created in the constructor before any draw. The legacy `stateHash` stays byte-identical forever; a separate `stateHashFull` covers new state, rng2, props, craters, projectiles, statuses and the event stream.
4. **Budgets are gates with thresholds written in the plan** (section 9): 600 units on Marble <= 160 draws at the WORST legal type count (16+16 types), triangles per frame <= Ancient measured x 1.25, sim <= 2 ms/tick at 300 units and Ancient within +5% of an in-process baseline, packed MINIFIED fragment <= 5,000,000 B (hard fail; raising it is the user's decision and goes in the final message), <= 500 published files, 48 parts per model, 16 types per team, heap plateau after a 40-battle soak.
5. **A unit is done only when the contract matrix is green** (spec U1): non-fallback model, far mesh readable, every requestable clip registered with timing, death/hit reactions per cause, projectile row with look and sound, audio profile, text (>= 11 strings, >= 15 for heroes and bosses, one line that names its mechanic), codex entry with counters row, balance row inside [30%, 62%] field win rate, membership in a campaign mission, survival pool and Quick Battle faction.
6. **Fictional, toy-box, kind.** Invented realms; no real nations, wars, orders, extremists, brands, flags, camo that matches a real army, symbols with real associations, or other companies' franchise units. Visual and verbal bibles per era (spec V1) with banned lists, and a checker.
7. **Real assets from the internet** under CC0 / CC BY 3.0/4.0 / PD with the existing licence gate plus a per-row provenance check, credited in the in-game Credits; synth fallback for every cue; honest about what nobody listened to.
8. **Studio finish per era**: identity (feel sheet), look (accent, diorama, map, title strip, chrome), music, tutorial, set-pieces, humour arc. Nothing placeholder.
9. **Verification is independent and evidence-based**: criteria ER1..ER24 registered in code and generated into the report; negative controls prove each new check can fail; two QA rounds by fresh agents who do not see builder notes or each other's reports; an explicit unverified list.
10. **The program survives context loss**: a task ledger, `STATUS.md`, WIP commits on a cadence, resumable workflows that write their outputs to files.

## 2. Architecture (maps 01, 05, 06; q1_engine Q29)

- **A1 Registry.** `src/content/registry.js` (pure, leaf data -> registry -> sim) merges data manifests `era_<id>/data.js`. Four merge kinds, not one: id-map (units, factions, arenas, props, missions, achievements...) that throws on duplicates; ordered list (categories, themes); singleton defaults (DEFAULTS); append-array (MATERIALS, metals, emblems, palettes: new entries appended, saved bytes never move). Era order is explicit in the generated manifest, not by directory sort. Recipes register into `gencore` at pack load (registry never imports recipes: no cycle). `stats.js` keeps importing the Ancient table only (frozen `K` and `roleEfficiency` constants) so saved customs never re-price; every other sim import reads the registry. `World` always receives merged defs; era scoping is an explicit argument of `generateArmy`, `WaveSystem`, `counterTable`, `scoutReport`, daily and survival (default `'ancient'` for every existing caller, and unknown faction throws).
- **A2 Ids.** Ancient ids frozen (ledger test G3). New ids unique by construction; prefixes `med_ mod_ sf_` for props, parts, cues, achievements, abilities, missions, puzzles; shared generic props stay `any`. Tombstone kinds `part faction mission era projectile` added first. Lint: no Ancient id literal in `src/sim/**` outside the era kit.
- **A3 Save (additive, no version bump).** `progress.stars` stays a flat global-id map; `progress.eras{id:{opened,last}}`, `progress.lastEra`, `survival.eras{id:{best,bestWave,board}}`, daily rows carry `era`, `stats.campaign.completedEras`, `seen.whatsnew_v2`. Mutator thresholds stay 3..27 total stars across all eras. Cross-version round trips tested both directions against the tagged v8 build.
- **A4 Campaign factories + facade.** `createCampaign({id, raw, text, starTests, statTable, mutatorStars})`, `createPuzzles`, survival/daily by era; `content.campaignApi/puzzleApi` dispatch by global id; `content.eras[]` = `{id,name,accent,currency,acts,map,tagline,order,status}`; `status:'hidden'` eras do not appear in any UI (this is how an unfinished era can never leak). Router history stores `{id, params}` so Back keeps the era. `recordCampaign`, `missionLine`, next-mission lookup are registry-driven.
- **A5 Era in a battle.** `World({era})` selects the kit: barks, lessons (+ new detectors), waves and bosses, god powers (6 per era), mascot/intervention, pacing record (`stalemate*`, dry ladder, time limits), `env.gravity` as a multiplier on every gravity use including per-def projectile gravity. `arena.env.era` (omitted when ancient) drives music and ambience.
- **A6 Packaging.** All inline. `gen-registry` discovers `era_*`; one generated file per era so parallel teams never collide on a tracked file; generated registry files untracked or regenerated only by the integrator. Per-family byte report is a gate artifact. Models and clips build lazily per era on first use; boot builds only the active era.
- **A7 Tooling is era-aware and strict.** `--era=<id|all>` everywhere; `tests/_eras.mjs` (`eachEra` asserts the era list equals the registry list and counts assertions; zero-assertion tests fail); per-era manifests state EXACT counts (Ancient 43/16/41/9/6); content agents may not edit thresholds, bands, floors or goldens (they file requests to TOOLS).

## 5. Models, rigs, animation (maps 03, q1_content; ANIM + UNITS)

- **Far-mesh-first discipline.** The player sees the far mesh at the default camera for every vehicle, siege engine, boss and mech (lodK2 starts it at 25-29 u). Look-dev renders far at 40 u and 80 u; the defining feature (barrel, rotor, wing, antenna, blade) must keep >= 60% of near-silhouette pixels; features are >= 3x3 voxels or aligned to even grid coordinates; a builder lint runs `downsample2` and fails on feature loss; rotor = dense disc or a far-mesh blur part; far tri budgets per class (vehicle <= 6 K, boss <= 15 K); dragon wings >= 3 voxels thick. `perf_assert` computes the worst army from far+near budgets.
- **Rosters before volume (DS):** `rosters.md` per era, 34 rows with id, faction, role, rig, weapon style, height class, tags, silhouette discriminator, counters, clip set, reaction set, audio profile, joke engine and the bark roles; contract: no two units share (role, rig, weapon style, height class, tag set) unless named variants; <= 2 units per faction share a body type; every faction has a silhouette-unique unit; boss table of 15 with one non-scaled-hum1 silhouette per era boss.
- **Rigs** (rig tables in `docs/spec/rigs.md` with errata; one tracer per rig): trebuchet1, ram1, dragon1 (+ wyvern), gun1 (howitzer, AT, mortar, HMG, AA; lite crew of 6 parts), tank1 (hull, turret, gun; treads prototyped before the rig is frozen: scroll vs wheels vs short period; rotors blur), car1, heli1, drone1, hover1, insect1 (+ queen scale), quad1 alien species, walker: **at most one "suited giant" (hum1 x2.4); other mechs get their own rig** (reverse-knee rigid legs via `gait.plantRigidLeg`, ground-shake event, topple death). Engine support: `meta.driven`, `extra.aim` + `meta.aimParts`, `meta.crewTable`, `meta.hover`, `meta.bounds` (cull, previews, Codex framing), airborne look spec (altitude by class, shadow blob size/opacity, banking from `vx`).
- **Clips:** new ids only, no collisions (gun reload is `reload_gun`; a test asserts new ids exist in no registered rig and in no `DEFAULT_META`); `DEFAULT_META` rows first; hit-agreement tolerances extended to every attack clip (rate-limiting clips +-5%); a test runs a battle with `DEFAULT_META` and with baked clips and bounds the divergence. List per rig in the spec (about 3 deaths + 2 hit reactions per rig), lazily baked per rig.
- **Spikes in P0 close the model risks:** rifle pose on 3 body types x helmets x power armour (clipping metric; fallback = `gunner` body module with foregrip attach or IK offhand), tread/rotor in far LOD, mixed voxel size (keep at 0.1 vs 0.2), crew budget on tank1, mech gait.
- **References:** every hero model has 3-5 CC0 silhouettes/photos in `docs/eras/ref/`; evaluate CC0 kit voxelisation for proportions only. Iteration caps: infantry 2, vehicle 3, boss/hero 4; acceptance checklist per model (40 px silhouette, far readability, tint %, near/far tris, preview framing). Hit/flinch/death filmstrips per rig read by an agent that did not build it.

## 9. Verification (the part that makes it true; owner TOOLS, independent of content agents)

**Criteria ER1..ER24** (registered in code via `criterion(id, ...)`, report generated from `.cache/gate/criteria.json`; a criterion with zero assertions or not executed is UNVERIFIED): ER1 Ancient identity G1..G10. ER2 registry integrity (collisions, DAG, order, tombstones). ER3 unit contract matrix (U1) incl. recolour detection by silhouette hash. ER4 far-mesh readability. ER5 clip/reaction coverage and timing agreement. ER6 mechanic tests S28..S45 + ablation (feature off shifts win rates by a stated minimum) + mechanic-coverage metric (each ability/projectile fires >= N times and changes outcomes in the era fuzz). ER7 balance: counters decided as **>= 200 battles per asserted pair, Wilson 95% lower bound >= 55% and point >= 65%**, claimed non-counters contain 50%, designed direction written BEFORE measuring, plus mechanic-off control; U5c field win rate in [30%, 62%]; mirror 45-55%; fuzz termination >= 99%, median 60-120 s; first-contact and dead-air metrics; S5-S9, U8 soldier fuzz, share fuzz per era. ER8 `campaign_play`: for every mission, through the real UI (chooser -> pin -> Deploy clicks -> reference army -> fight to `ended` -> stars written -> next pin unlocked -> NEXT navigates -> Back keeps era), winner equals the recorded bot result; a no-thought autofill bot wins <= 40% in acts 2-3 and <= 60% in act 1; a mechanic-blind variant loses >= 70%; win rate monotone over a bot skill ladder; no harness-only workaround allowed.
