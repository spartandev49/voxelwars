## 0. Non-negotiables

1. **Ancient does not change** and we prove it: ids, stats, layouts, text, sounds, pixels, screens, saves, clip data, LOD decisions. Goldens G1..G12 are recorded from a verified baseline BEFORE the first engine edit (section 3). Every change that touches an Ancient path is listed in the **AP table** (all areas, not only sim: render, UI, audio, shared kit files) with its policy: bit-identical opt-in by default; a deliberate delta needs a named re-record under two signatures (the author cannot sign).
2. **One engine, data-driven eras.** Eras are packs in `src/content/era_<id>/`, registered and merged. No `if (era === ...)` in engine code. Every new def/projectile/prop/hazard field **defaults to legacy behaviour**; era data opts in explicitly; a test asserts all 43 Ancient defs leave every new field undefined and `JSON.stringify(def)` is unchanged.
3. **Determinism.** 30 Hz sim, one seeded stream. **Bit equality holds only WITHIN one JS engine**: round 3 measured that `Math.sin/cos/pow` differ by 1 ulp between Node 22 and Chromium 141 and an unmodified Ancient 300-unit battle is bit-identical to tick 900 but diverges by tick 2500; so records carry `engine: node|chromium`, and cross-engine claims are statistical (AR6). New randomness only from per-mechanic forks of the main RNG (`fork('era:burst')`, ...; a fork is `new RNG(parentState ^ hashString(label))`, so creation order is irrelevant; labels form a never-renamed registry in `spec/M` with a collision test); the legacy `stateHash` stays byte-identical forever; `stateHashFull` covers new state (y, layer, state, aim, ammo, shield, cloak, status timers, fork states, projectile pool, craters via height checksum, prop hp/team) and the event stream.
4. **Budgets are gates with thresholds** (section 9): at the worst legal type count (16+16) draws <= 160 and triangles <= Ancient measured x 1.25; `view.update` <= Ancient measured x 1.25 plus tier ceilings; sim, three independent gates: (i) Ancient regression A/B within max(5%, 3 sigma from an A/A run); (ii) new-era scenarios <= 2.0 ms at 300 units and 3.0 ms at 500 (absolute ceilings); (iii) the era-total delta <= 0.5 ms at 300 / 0.8 at 500, allocated across modules by script and checked by ablation; packed MINIFIED fragment <= 5,000,000 B (warn 4,500,000; raising it is the user's decision and goes in the final message); published files <= 500 counted server-side; <= 48 parts; <= 16 types per team; heap plateau after a 40-battle soak that alternates eras.
5. **A unit is done only when the unit contract `UC` is green** (spec `UC`): non-fallback model, far mesh readable at its own switch distance, every requestable clip registered with timing, death/hit reactions per cause, projectile row (look + sound), audio profile, text (>= 11 strings, >= 15 for heroes and bosses, one naming its mechanic), codex entry with a counters row, balance row in [30%, 62%] field win rate (bosses/support/siege judged in their own modes), membership in a campaign mission, survival pool and Quick faction. A **tracer** meets `UC` minus the clauses that need later phases (list in `spec/S-slice`).
6. **Fictional, toy-box, kind.** Invented realms; no real nations, wars, orders, extremists, brands, flags, uniforms/camo matching a real army, symbols with real associations, or other companies' franchise units. Enforced by `VB` (visual bible: palette tables with a banned reference list and a CIEDE2000 minimum distance test, emblem allow-list by signed registry append, model rules: no letters/numbers, no star/cross/crescent at flag size, no three-band flag layouts) and by the text sweep.
7. **Real assets from the internet** (CC0, CC BY 3.0/4.0, PD; no SA/GPL/NC) with a per-row chosen licence and a licence-page snapshot, credited in-game; synth fallback for every cue; honest about what nobody heard.
8. **Studio finish per era**: feel sheet, look, music, tutorial, set-pieces, humour arc. Nothing placeholder; the console is clean (zero errors/warnings across `campaign_play` and `uiscan`, empty allowlist).
9. **Independent, evidence-based verification**: criteria registered in code, every check has a registered negative control (a check without one is UNVERIFIED), two QA rounds by fresh agents who do not see builder notes or each other's reports, and an unverified list that says plainly that comedy, feel, set-pieces and readability were judged by model panels, not a person.
10. **The program survives context loss**: task ledger, `STATUS.md`, `wip/` branch commits at least hourly, resumable workflows that write outputs to files.

## 2. Architecture decisions

- **AR1 Registry** (`src/content/registry.js`, pure; leaf data -> registry -> sim). Four merge kinds: id-map (throws on duplicate, naming both eras), ordered list, singleton default, append-array (MATERIALS, metals, emblems, palettes). Era order explicit in the generated manifest. `registry.freeze()` is called once by the pack loader; `buildSimDefs`, `defsOr`, `K`, `roleEfficiency` throw (or recompute under a version key) if used before freeze; `registry.verify()` checks arena->recipe, unit->model/clip/rig/projectile/cue, tombstones. `era_*/data.js` may import leaf data only (lint list); DAG test loads the registry in Node with a stubbed `window` and in esbuild. Recipes register into `gencore` at pack load (registry never imports recipes). `stats.js` keeps the Ancient table only for `K` and `roleEfficiency` (frozen constants). Generated registry files are committed, deterministic, sorted, one per era, gated on "regeneration produces no diff". Hidden eras still ship in the byte count (single IIFE).
- **AR2 Ids.** Ancient frozen (G3). New ids unique; prefixes `med_ mod_ sf_` for props, parts, cues, achievements, abilities, missions, puzzles, god powers, set-pieces; shared generic props stay `any`. Tombstone kinds added first (`part faction mission era projectile`). Lint: no Ancient id literal in `src/sim/**` except an allowlist of global utility units (`battle_goat`, `sacred_chicken`) with a test that lists them.
- **AR3 Era precedence.** `World.era` is explicit (UI sets it from the mission's era or the Quick era chip). `arena.env.era` supplies visuals/audio only. An arena/army era mismatch uses the World's era kit.
- **AR4 Save (additive).** `progress.stars` flat global ids; `progress.eras`, `progress.lastEra`, `survival.eras`, daily rows with `era`, `stats.campaign.completedEras`, `seen.basics`, `seen.beats`, `seen.whatsnew[era]`; settings `gore` gains `auto` with a `goreChosen` marker migration (CU4). Mutator thresholds stay 3..27 total stars. Both-direction round trips against the baseline build.
- **AR5 Campaign factories + facade.** `createCampaign`, `createPuzzles`, survival/daily by era; `content.campaignApi/puzzleApi` dispatch by global id; `content.eras[]` with `status: released|hidden` (hidden eras appear in no UI); router history stores `{id, params}`. **Mission data is machine-readable** (`MS`, section 8).
- **AR6 Timing regime (one).** Sim attack timing reads `ClipLib`. Node harness, goldens, balance, `campaign_play` and the browser ALL call the same `ensureEra(era)` before `new World`: synchronous, bakes the era's clips, compiles model tables, warms its roster; the World asserts `ClipLib.version` is constant for the battle; `DEFAULT_META` is a fallback a test proves unused by any registered def; G1 is recorded under both regimes from the baseline and the doc states which one the shipped game matches; **Comparator classes (round 3 B1):** (a) bit equality only within one engine (Node vs Node, Chromium vs Chromium, baseline build vs candidate build in the SAME engine); (b) cross-engine: report the first-divergence tick and require the statistical bound (200 battles: win rate within 3 points, median end tick within 2%); (c) outcome-critical stored artefacts (campaign `reference` armies, puzzle solutions, star thresholds) must win with margin (>= 8 of 10 seeds) in BOTH engines. G1/G6 are Node-engine records and no Node record is bit-comparable to the shipped game after about 1,000 ticks; every stored record carries its engine and `release_check` refuses cross-engine comparisons. `ensureEra` cost is measured per era with a ceiling; if over, bake at boot (cost is time, not bytes).
- **AR7 Packaging.** Per-family byte report as a gate artifact; models/clips lazy per era via `ensureEra`; hidden eras counted.
- **AR8 Tooling is era-aware and strict.** `--era=<id|all>` everywhere; `tests/_eras.mjs` `eachEra` asserts the era list equals the registry and counts assertions (zero-assertion test fails); per-era manifests state EXACT counts; content agents may not edit thresholds, bands, floors or goldens (requests to TOOLS).
- **AR9 Custom soldiers in new eras.** Per-era `custom_classes` rows (weapon classes, shields, ability presets, cost-role terms) registered through the registry and passed as `statsToUnitDef(cs, {era})`; era derived from the main weapon's part meta (no new save field); default `'ancient'` with byte-identical Ancient rows (golden: costs of 200 random Ancient customs from G5); refit applies only to new rows; `roleEfficiency` per era; `power.js` extended (below); owner and files listed in `spec/AR`.

Gates run on a **snapshot** (`git worktree add .cache/snap/<sha>`, node_modules symlinked); "green" is only ever applied to that sha; `wip/` branch for hourly commits; only snapshot-green shas are tagged `green-N` and pushed to the work branch; freeze protocol for P5/P6 (agents stopped, tree clean, no builder runs during QA).

## 5. Models, rigs, animation (RA; maps 03; ANIM-RIGS, ANIM-CLIPS, UNITS)

- **Far-mesh-first.** Truth table from `lod.js` (a coarse cell exists iff >= 3 of its 8 fine voxels are solid, cells aligned to the part grid origin): a feature survives faithfully when its cross-section is >= 2x2 AND even-aligned in both perpendicular axes, or >= 3 wide in one axis; 1x1 never survives; the `downsample2` lint is the arbiter (fails the builder on feature loss). Look-dev renders far at the model's own switch distance (`56*sqrt(lodK2)` and `56*0.35*sqrt(lodK2)`) and at 80 u; the defining feature keeps >= 60% of the near silhouette pixels; far tri budgets per class (vehicle <= 6 K, boss <= 15 K); dragon wings >= 2 voxels thick with membranes dense enough to survive; rotor = dense disc or far blur part.
- **Rosters before volume** (`design/<era>/rosters`): 34 rows with id, faction, role, rig, weapon style, height class, tags, silhouette discriminator, counters, clip set, reaction set, audio profile, bark roles, joke engine; contract: no two units share (role, rig, weapon style, height class, tag set) unless named variants; <= 2 units per faction share a body type; every faction has a silhouette-unique unit; boss table of 15 with one non-scaled-hum1 silhouette per era boss.
- **Rigs** (tracer per rig; part tables in `docs/spec/rigs.md` with errata): trebuchet1, ram1, dragon1 (+ wyvern), gun1 (howitzer, AT, mortar, HMG, AA; lite crew of 6 parts), tank1 (hull, turret, gun; treads prototyped before freezing), car1, heli1, drone1, hover1, insect1 (+ queen scale), quad1 alien species, mechs: at most one "suited giant" (hum1 x2.4), others own rig (reverse-knee rigid legs via `gait.plantRigidLeg`, ground-shake event, topple death). Engine support: `meta.driven`, `extra.aim` + `meta.aimParts`, `meta.crewTable`, `meta.hover`, `meta.bounds` (cull, previews, Codex framing).
- **Clips:** new ids only (gun reload is `reload_gun`; a test asserts new ids exist in no rig and no `DEFAULT_META`); hit-agreement tolerances extended to every attack clip (rate-limiting clips +-5%); per rig about 3 deaths + 2 hit reactions listed in the spec; reaction tables per rig as data (M17t).
- **Airborne look:** altitude by class, shadow blob size/opacity from altitude, banking from `vx`, rotor representation per LOD.
- **Spikes in P0** close model risks (above). References: 3-5 CC0 silhouettes/photos per hero rig in `docs/eras/ref/`.
