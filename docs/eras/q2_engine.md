### Q1 (BLOCKER) The sim reads a mutable global clip table; goldens, balance, `campaign_play` and the shipped game run under different timing regimes, and lazy per-era baking adds a third
**Question**: Under which `ClipLib` state are G1, G6, the balance harness, ER7, ER8 and ER13 recorded and replayed, and why would the Chromium result equal the Node result?
**Evidence**: `combat.js:240,252` `ClipLib.dur(clip)` / `ClipLib.hit(clip)` (no rig argument) set `stateDur`, `hitAt` and `rate` for every attack; `combat.js:214` `deathLinger` uses `ClipLib.dur(clip, defRig)`. `anim/clips.js:76-91,93-110`: until `register()` runs, timing comes from `DEFAULT_META`, unknown ids fall back to `idle`; the plain slot is owned by the first registering rig (or hum1). `registerAllClips` is called only in `app/main.js` and anim tests; `grep registerAllClips tools/` finds only `tools/anim_page.js`: `tools/lib/harness.mjs`, `balance.mjs` and `perf_sim.mjs` never bake, so every Node number (G1, G6, balance report) is DEFAULT_META timing, while the shipped game and `campaign_play` are baked timing. The plan keeps both: ER8 "winner equals the recorded bot result" through the real UI (Chromium, baked) and ER13 "Node-vs-Chromium `stateHashFull` parity", yet section 5 only promises "a test runs a battle with DEFAULT_META and with baked clips and bounds the divergence" (no bound given) and "+-5% for rate-limiting clips". Parity and "bounded divergence" cannot both hold: windup/hit time for a non-rate-limited clip differs by the full dur difference.
**Failure scenario**: Mission 7 reference army wins in Node at seed 1 (DEFAULT_META), loses in the Chromium run (baked burst windup 0.4 s longer); `campaign_play` goes red, the rule "no harness-only workaround" forbids the usual fix, and the only exit is re-recording G6 in Chromium after the balance numbers were measured in Node. Lazy baking makes it worse: a Quick Battle that creates the World before the era's clips are baked runs on DEFAULT_META, then `register()` bumps `ClipLib.version` mid-battle and timing changes in flight.
**Required plan change**: (1) Declare ONE canonical timing regime: Node harness, goldens and balance call the same `registerAllClips(era)` as the browser (for Ancient this must reproduce today's numbers: record G1 under both regimes from the tag and state which one the shipped game matches); DEFAULT_META becomes a fallback that a test proves is never used by a registered def. (2) `ensureEraClips(era)` is synchronous and runs before `new World`; the World asserts `ClipLib.version` is constant for the whole battle. (3) State the numeric divergence bound (for example: win rate of a 200-battle sample differs by <= 3 points and median end tick by <= 2%) and who measures it. (4) ER13 parity is only claimed under (1).
