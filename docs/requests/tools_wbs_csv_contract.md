# tools_wbs_csv_contract (TOOLS-VERIFY -> COORD): what `docs/eras/wbs.csv` must look like for `tools/wbs.mjs` and P0E-10, P0E-11, P0E-15

`docs/eras/wbs.csv` is generated by an agent (plan section 12, P0E-10); `node tools/wbs.mjs` and `node tools/p0_exit.mjs` read it. Contract (full text: `docs/eras/spec/VF-impl.md` section T6, tool header of `tools/wbs.mjs`):

* header exactly `wp,owner,preds,phase,hot_files,size,accept,ladder_rung,no_regret,spec`; extra columns are allowed; RFC 4180 quoting (`"a b"`);
* `wp` unique; `preds` = WP ids separated by `;` or spaces, all existing, none in a LATER phase than the WP; `phase` P0..P6; `size` S, M or L (1, 2, 4 sessions);
* `ladder_rung` blank or 1..6 (the cut ladder of plan section 13); `no_regret` yes or no on EVERY row;
* `owner` carries an instance suffix where a role has several instances: `REVIEWER#1`, `REVIEWER#2` (P0E-15 wants at least two);
* `spec` non-empty on rows that produce a document (each creates review demand for the reviewer queue);
* WP ids follow the class convention of `docs/eras/wbs_rules.json` so the granularity check can count them: `UNIT-H-<ERA>-nn` (humanoid units, 4 per WP), `UNIT-X-<ERA>-nn` (vehicles, mechs, bosses, siege, aliens, 1 per WP), `PROP-<ERA>-nn` (6 per batch), `ARENA-<ERA>-nn`, `MISSION-<ERA>-nn`, `PUZZLE-<ERA>-nn` (2 per WP), `TEXT-<ERA>-<layer>` (+20% rewrite reserve), `AUDIO-<ERA>-<group>` (4 families per WP), `RIG-<rig>-TRACER|CLIPS|REACT`; `<ERA>` is MED, MOD or SF. If the generator prefers other ids, edit the `match` regexes of `wbs_rules.json` (a class with zero matching rows is reported loudly, not skipped);
* `count: null` classes of `wbs_rules.json` (humanoid vs special units, text layers, audio families, rigs) need their manifest counts filled in by COORD once the rosters are machine-readable; until then they report PENDING.

First run: `node tools/wbs.mjs --check`, then `node tools/wbs.mjs --paste --insert-markers` once (adds the `<!-- wbs:begin -->`/`<!-- wbs:end -->` pair to plan section 12 and to `STATUS.md`), afterwards `node tools/wbs.mjs --paste`. Plan lint rule PL12 then checks the pasted block instead of the prose estimate, and the prose figures of section 12 (which the lint currently finds inconsistent: "8.5-15 days" for 640-700 sessions at c x u 2.5-3.5 is 9.9-15.2) can be replaced by it.
