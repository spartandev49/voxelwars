# spec/editors.md — Arena Builder, Soldier Workshop, Voxel Painter (owner EDITORS; follows spec/ui.md kit)

Tablet+ only (>= 768 px wide, pointer or touch). Phones see the friendly notice (`phone_notice`, ui.md §4). All editors: undo/redo (Ctrl/Cmd+Z, Shift+Z, buttons, 100 steps, delta-compressed, `core/undo.js`), autosave draft every 20 s (key `vw.draft.<editor>`, spec §11), explicit Save with name, export/import share code, validators with fix-it messages, keyboard shortcuts overlay (`?`), tooltips with the real shortcut, and sounds.

## 1. Arena Builder
Layout: 3D viewport (orbit camera as in battle, top-down toggle) centre; left toolbar; right inspector; bottom bar (size, name, Save, Share, Playtest, Undo/Redo).
Tools (each with radius 1-20 u, strength, shape circle/square, falloff, hotkey; 16 tools):
1. **Raise/Lower** (LMB raise, Shift lower), 2. **Smooth**, 3. **Flatten** (click sets target height, drag flattens; alt-click samples), 4. **Paint material** (16 materials; "paint under water" ok), 5. **Water/Lava level** slider (+ lava toggle), 6. **Noise** brush (adds seeded fbm), 7. **Ramp/Road** line tool between two points (cuts a walkable ramp, paints cobble), 8. **Stamp** presets (hill, crater, mesa, trench, island, ridge), 9. **Props** (catalog by category with search, rotate R, scale mousewheel+Alt, Shift scatter brush with density, delete tool, snap to cell, mirror about arena axes; lists every catalog entry with `place !== false`, i.e. 40 of the 41 (everything except `crowd`; world.md §2)), 10. **Hazards** (quicksand, spikes, fire pit, boulders lane, geyser, lava) as radius circles, 11. **Zones** (drag A/B rectangles; must fit and not overlap; shown as translucent blue/red overlays), 12. **Symmetry** (off / mirror X / mirror Z / rotate 180°) applying to terrain, paint and props, 13. **Generate** (recipe dropdown + seed + "Reroll" + "Apply to terrain only / props only / both"), 14. **Environment** (time slider 0-24 with live sun/sky, weather, fog, wind, theme music mood), 15. **Info** (name, author, description, tags), 16. **Markers & objective** (new): place, drag and delete the objective markers of `arena.markers` (<= 8; types `hill`, `exit`, `vip_start`, `general_spawn`, `waypoint`; radius 1-30 u, default 4, `hill` default 6; drawn as ground rings with a type icon) and pick the arena's default **objective** (Eliminate / Kill the general / Hold the hill / Protect the VIP / Destroy the gates). Choosing an objective highlights the markers it needs and lists the missing ones in the validator panel (hold_hill needs a `hill`; protect_vip needs `vip_start` + `exit`; kill_general needs `general_spawn`; destroy needs >= 1 `gate_door` prop). The picked objective is stored on the arena as a suggestion and pre-selects the Quick Battle objective picker (world.md §8) when the arena is played; markers are the same data the nine hand-written campaign missions use (world.md §5).
Size: small/medium/large (resizing resamples the map; asks via in-page modal if content would be lost).
Validators (shown in a panel with "Fix" buttons): both zones exist, inside bounds, not overlapping, >= 30 walkable cells each, NOT underwater (fix: raise), a path exists between zone A and zone B on the nav grid for unit radius 0.45 **and** 0.55 (flood-fill; fix: "carve a ramp"), props count <= 1500 and unique prop types <= 41, hazards <= 60, markers <= 8 and inside bounds, the picked objective's markers exist, name 1-32 chars. Save is allowed with warnings; Playtest is blocked only by blocking errors.
**Playtest** button: opens quick setup with this arena preselected and returns to the editor with state intact (not re-generated).
Library ("My Arenas" + presets): thumbnails (<= 6 KB jpeg-ish data URL rendered from the viewport), rename, duplicate, delete (in-page confirm modal), export code, import code (paste box, strict validation errors in plain English).

## 2. Soldier Workshop
Layout: left = category tabs and part pickers; centre = 3D turntable (drag orbit, zoom, clip picker idle/walk/attack/block/death, weapon swing preview, scale reference with a hoplite ghost toggle); right = tabs Stats / Abilities / Colours / Personality / Voxel Paint; bottom = name, cost, Save to roster, Use in battle, Share, Randomise, Reset.

**Parts come from the registry, never from a hard-coded list.** Every picker is `listParts(category, unlockedKeys)` of `content/era_ancient/parts/_registry.js`; a locked part shows a lock and its `unlock.hint`; a category with no entries shows an empty state ("Nothing here yet"). The Workshop tabs map onto the 12 registry categories (`CATEGORIES`: helms, hair, faces, tunics, armors, shoulders, legs, skirts, capes, backs, mains, offs): **Head** = `helms` + `hair` + `faces`; **Torso** = `tunics` + `armors`; **Shoulders** = `shoulders`; **Legs** = `legs` + `skirts`; **Cape** = `capes`; **Back** = `backs`; **Main hand** = `mains`; **Off-hand** = `offs`. Blueprint slots (spec §5, `blueprints.js SLOTS`): `head.helm`, `head.hair`, `head.face`, `torso.tunic`, `torso.armor`, `legs.armor`, `legs.skirt`, `shoulders`, `cape`, `back`, `main`, `off`. - **Acceptance minimums** for the library (the Workshop shows what is registered; these are the bar UNITS-LIB must clear): helms >= 18, hair >= 12, faces >= 10, tunics >= 5, armors >= 7, shoulders >= 4, legs >= 4, skirts >= 3, capes >= 4, backs >= 5, mains >= 18 (including bows, a sling and the 7 silly weapons), offs >= 9.
- **Body**: type slim / average / stocky (`BODY_TYPES`) + height slider 0.9-1.2 (cost impact); skin swatches (13: Porcelain, Fair, Olive, Tan, Bronzed, Brown, Deep, Ebony + Goblin green, Smurf blue, Stone, Gilded, Ghost), hair colour (10 swatches), eye colour (6).
- **Colours**: primary, secondary, trim, cloth (4 pickers), metal (bronze / iron / gold / silver / steel / blackiron), emblem (none + lambda, eye, sun, boar, eagle, star, skull, wave, bolt = 10); 8 ready palettes.

**Stats (CustomSoldier `stats`, spec §5.1)**: seven point-buy stats, 100 points in total, per-stat caps and diminishing returns: `hp` 0-30, `damage` 0-30, `attackSpeed` 0-20, `speed` 0-20, `armor` 0-20, `range` 0-10, `morale` 0-10. `range` points add to the weapon class's base range (+0.1 u per point, at most +1.0 u); because the weapon-length rule (spec §4.1) clamps the compiled weapon to `range + radius + 0.3` u, range points are also what lets a long weapon keep its full length. The **weapon is not a stat and not a second field**: it lives only in `blueprint.main`; its registry `meta.style` sets the weapon class and base (`thrust` = spear, `pike`, `slash|overhead|bash` = melee, `throw` = thrown, `cast` = magic, `shoot` = ranged). **Cost** = `costFormula(stats, weapon, abilities)` from `sim/stats.js`, applied to the DERIVED def (`statsToUnitDef`), clamped so that no combination exceeds 1.35x the cost-efficiency of the best shipped unit of the same role (checked by the fuzzer). Total cost shown live with a "Power rating" radar.
Abilities: pick up to 2 from the class list legal for the weapon/body class (e.g. `kick` needs melee, `heal_pulse` needs staff/scepter, `rage` any melee) with cost impact. AI style: charge / hold / skirmish / flank / guard / support.
Personality: name (1-40 chars; random funny name generator button: "Sir Chadius the Mildly Concerned"), catchphrase on spawn (<= 40 chars), 3 death quotes (<= 40 chars each, defaults generated), voice pitch 0.7-1.4.
Roster: "My Soldiers" (up to 24), duplicate/edit/delete, thumbnail; custom soldiers appear in the placement palette under "My Soldiers"; max 16 distinct types per battle includes them.
**Hard guards** (the numbers of spec §5.1; `compileSoldier` already enforces the radius and the 1,500-voxel paint cap): weapon reach <= 3.6 u; **collider radius 0.3-0.7 u**, defaulting from the body type (slim 0.50, average 0.55, stocky 0.62; `BODY_RADIUS`), always clamped by `compileSoldier`; **scale clamp**: the effective scale per axis is `clamp(heightSlider x bodyTypeScale[axis], 0.85, 1.35)` with `bodyTypeScale` = slim (0.92, 1.0, 0.92), average (1, 1, 1), stocky (1.12, 0.98, 1.12) — the clamp is applied AFTER the multiplication, so a slim soldier at height 0.9 still measures 0.85 on x and z, and the largest possible soldier (stocky at 1.2) is 1.344 on x and z, inside the cap (no giants); parts <= 48; nav radius capped. Imported blueprints are re-validated and re-costed (cost is never trusted from the file); unknown part ids are rejected with a "Did you mean 'x'?" suggestion.

## 3. Voxel Painter (opens from the Workshop "Voxel Paint" tab)
Edits one part at a time on its **fixed canonical grid** (spec §4.1; `DIM` in `parts/_kit.js`): body, head, crest, armUL, armLL, armUR, armLR, weapon, offhand, legUL, legLL, legUR, legLR, back, cape, cape2 (16 parts; the part picker shows the part names, never raw ids). Views: 3D (orbit, click to paint on faces with a hover cursor), 2D **slice** view (layer slider along any axis, click/drag to paint, large pixels, grid, onion-skin of adjacent layers), with a mini preview of the whole soldier wearing the edit (live, animated optional).
Tools: pencil (add voxel on face), eraser, paint (recolour existing), fill (flood 3D / layer), line, box (filled/hollow), eyedropper (alt/long-press), select+move (box), mirror X/Y/Z toggles (X defaults on for symmetric parts), brush size 1-3, undo/redo, clear part, reset to generated, copy/paste part to opposite side (flip), rotate/flip selection. Palette: 24 default swatches + HSV picker + recent colours + hex input + "team tint" and "glow" flags as material toggles (`F_TEAM`, `F_GLOW`); import/export palette as a share string. Painted voxels are stored per part as `bp.paint[partId] = {sx, sy, sz, rle}` (the painter saves `diffPaint(edited, generated)`: run value 0 = untouched, 1 = erase the generated voxel, anything else = the voxel `(flags<<24)|0xRRGGBB`); the cap is **1,500 painted voxels per part** (`PAINT_CAP`), and the grid size must equal the canonical size or the blueprint is rejected.
Touch: tool buttons large; two-finger orbit/zoom in 3D; slice view recommended on touch (default on touch devices); pointer-event driven; Playwright tests synthesise pointer sequences for paint/erase/fill/mirror/undo.

## 4. Share codes UI
Export: shows the code, its length and size class (S <= 1.8k, M <= 8k, L <= 38k characters, `share.js sizeClass`), copy button (clipboard with fallback to a selectable textarea), "Download" via `downloads.save` when available (`.vwarena` / `.vwsoldier` / `.vwarmy`, same string), QR not needed. A code over 38,000 characters is not offered as text: the UI says "Too long: 41,203 > 38,000 characters" and offers the file instead. Import: paste box, button, strict validation with plain-English errors ("This code is for an arena, but you are importing a soldier", "Unknown prop 'dragon_egg' — the code may come from a newer game version", "Too long: 41,203 > 38,000 characters"), preview before accepting; files are accepted up to the parser's 400,000-character limit. Round-trip fuzz tests in `tests/save/`.
