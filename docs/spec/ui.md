# spec/ui.md — Art direction, tokens, components, screens, HUD, input

## 1. Art direction: "Toy-box Olympus"
A playful, saturated, high-contrast cartoon world. The 3D scene is bright daylight Mediterranean with chunky voxel soldiers; the UI is a set of **sticker-like stone tablets**: deep-indigo panels with thick ink outlines, hard offset shadows and gold buttons that physically press. Humour is in the micro-copy and small motion (buttons squash, tablets wobble in). NOT parchment, NOT bronze/terracotta.
- Title composition: huge 3D voxel logo VOXELWARS (built from voxel letters, gold with ink outline, slightly tilted, floating with a slow bob + sun glint sweep) over a live diorama of a tiny battle on a floating island with clouds; menu tablets on the left; version tag bottom-left; "Press any key" splash first.
- Everything one `100%` height app. Single dark-first look (deliberate: game UI), `color-scheme: dark`. Tokens defined on `:root` first (no theme blocks needed because the page commits to one look), `body` background explicit.

## 3. Components (`ui/kit.js`; pure DOM builders, all `textContent`)
`button(label,{variant:'primary|secondary|ghost|danger', icon, onClick, sound})`, `tablet(title, content)`, `tabs`, `chip`, `slider(min,max,step,value,onInput)` (tick sound), `toggle`, `select`, `segmented`, `card(unit)`, `tooltip(el,text)` (hover + long-press, never the only way to learn a thing), `toast(text,{kind})`, `modal({title,body,buttons})` (replaces confirm; Esc closes; focus trap), `banner(text)` (round-start ribbon), `progress`, `meter(teamA,teamB)`, `kbd(key)`, `toolbar`, `emptyState`. Rules: focus-visible outline 3px gold; hit area >= 44 px; hover = lift 2px; active = sink 3px; transitions transform/opacity only; `prefers-reduced-motion` and the in-game Reduce Motion disable springs/wobbles; every control has an `id` and `aria-label` when icon-only; roles for tablist/menu/dialog; sound on hover (soft), click, confirm, back, error, toggle, tick.

## 4. Screens (each: layout, content, empty/error states, back/Esc, keyboard order)

- editor layer, base: `arena_builder`, `workshop`, `painter` (spec/editors.md).
Surfaces that are NOT router ids but are specified in §4a: the Scout report (panel in `placement` and `briefing`), Lessons (section of `results`), the Mutators picker (chips in `quick` and `survival`) with its HUD strip, Choreography (Settings toggles plus battle staging) and Teaching beats (HUD part).

## 4a. Meta surfaces (verification UI16-UI19; each: where it lives, layout, content, empty/error states, keyboard, touch)
All of them use the kit (§3), the sticker-tablet look, `textContent` only, sounds on every control, and obey Reduce Motion (staggers and pulses become instant). Copy is HUMOR's (humor.md tone rules).

1. **Daily Skirmish** (`daily`; Title tile with a "New today" badge until today's result is stored).
   - *Layout*: two columns from 900 px (single column below). Left: the **challenge card**: headline "Daily Skirmish" + the local date, arena thumbnail (`ctx.preview.arena`), chips for arena, budget ("8,000 drachmae"), your faction, enemy faction + style (balanced/rush/ranged/elite/chaos/counter) and difficulty, one HUMOR blurb, and the big gold **Play today's skirmish** button. Right: **streak and history**: streak counter, best streak, a 7-day strip (win / loss / missed), and a list of the last 30 results (date, result, % of army alive by cost, time).
   - *Rules of the day*: seeded from the **local calendar date** (the device's `YYYY-MM-DD`; the same date gives the same arena, factions, enemy style and seed); budget fixed at Battle 8,000, difficulty normal, no mutators, no objective override. `game.newSetup('daily')` builds it; Play goes to placement as usual (the chips stay as a header) and the results overlay shows the daily result card.
   - *Stars and result string*: ★1 win; ★2 win with >= 50% of the army (by cost) alive; ★3 win with >= 75% alive. The **copyable result string** is `VOXELWARS Daily 2026-10-06 | WIN | 62% alive | 1:34 | 2/3 stars`; the Copy button uses the clipboard and falls back to a selectable text box (spec §12 platform table).
   - *History and streak* (`vw.daily`, cap 60 entries): only the first completed run of a date is recorded; later runs are labelled "Practice" and change nothing. Streak = consecutive local dates with a recorded run (win or loss); a missed date resets it to 1 at the next run; the best streak is kept (lifetime stat `dailyStreak`). The card re-reads the date when the tab regains focus (midnight rollover).
   - *Empty/error*: no history yet: "No battles yet. Today's skirmish is waiting."; storage blocked: the history shows a "Not saving" chip and the streak is marked "this session only"; if the setup fails to build, a toast offers Quick Battle instead.
   - *Keyboard*: Tab order card, Play, Copy result, history; Enter = Play, C = copy the latest result, Esc = back to Title; history rows use roving focus. *Touch*: Play is full width and sticks to the bottom edge on phones; history collapses into a disclosure.

2. **Puzzles (6)** (`puzzles`; opened by the Campaign map's "Puzzles (6)" button; data in world.md §6a, progress in `vw.progress`).
   - *Layout*: a grid of six puzzle cards (3x2 on desktop, 2x3 on tablets, one column on phones). Card: number and title, arena thumbnail, the **goal** line with an icon ("Destroy both gates in 120 s"), chips **Budget 1,400** and **Par 1,000**, a strip of the unit icons the roster allows, three star slots, and **Play**. Selecting a card opens a side panel with the hint (collapsed behind "Need a hint?"), the best result (drachmae spent, time, stars) and "Reset best". All six are open from the start (they teach counter-picks, they are not a gate).
   - *Flow*: Play -> briefing overlay (goal, par, the restricted roster) -> placement with the palette limited to the roster, the budget bar showing a **par tick**, the enemy already placed (no auto-fill, no mutators) and a "Reset" button -> battle -> results with the puzzle's stars and **Retry** (R) / **Next puzzle**.
   - *Empty/error*: a puzzle whose data fails validation shows "This puzzle is being re-chiselled" on its card and a disabled Play; blocked storage shows "Not saving".
   - *Keyboard*: roving focus across the grid (arrow keys, both axes), Enter plays, H toggles the hint, Esc returns to the Campaign map. *Touch*: tap selects, the panel becomes a bottom sheet, Play is 44 px high.

3. **Scout report** (panel in `placement`; read-only twin in `briefing`).
   - *Layout*: a collapsible section of the placement right panel (open on the first visit, `aria-live="polite"`). Top: **Enemy forces**, the pre-battle reveal: chips by role with counts and the total cost of the enemy army as placed (nothing is hidden, it only aggregates). Below: up to five advice items from `Game.info.scout(team)` (`{severity:'weak|tip|strong', text, counters?:[unitIds]}`; an item that only carries `kind:'warn'` is shown as a Tip), sorted weak > tip > strong; each has a severity chip (**Weak spot** red / **Tip** gold / **Strong point** green), one sentence in the scouts' voice ("Enemy cavalry detected and you have no spears.") and **counter chips** (unit names). Clicking a counter chip switches the palette to that unit's faction tab, clears search and role filters and selects the unit as the brush; it places nothing.
   - *Briefing twin*: the same builder with no click-through: enemy composition chips plus at most two advice items.
   - *Empty/error*: "Place some soldiers and the scouts will tell you what they think."; if the advice call throws the panel shows the empty state, never an error toast. Refreshes on every placement change at <= 4 Hz.
   - *Keyboard*: the heading is a disclosure button (Enter/Space), counter chips are focusable buttons. *Touch*: on phones Scout is one of the placement bottom-sheet tabs.

4. **Lessons** (section of the `results` overlay, `ResultsData.lessons`, generated by `sim/lessons.js` from the event log).
   - *Layout*: below the stats tablet, a card "Cassandra's notes" with **exactly three lesson rows**. Each row: the announcer portrait (`who`, Cassandra by default), one observation in her voice ("I said the archers would die first. They did."), and a **fix chip** ("Try: spears in front") with a **Try it** button that returns to placement (same as Tweak) with the army kept and the fix's counter unit selected. Rows enter with a 400 ms stagger.
   - *Rules*: victories get three too (what nearly went wrong). When fewer than three patterns match, gentler generic lessons fill the gap; a lesson id is not repeated twice in a row across rematches.
   - *Empty/short battle*: under 10 s or fewer than 3 kills the card shows the generic lessons under the line "Too short to learn from. Cassandra recommends fighting longer."
   - *Keyboard*: Tab reaches each Try it button; T (Tweak) works anywhere on the results screen. *Touch*: rows stack, buttons 44 px.

5. **Mutators** (chip picker + HUD strip; data `sim/mutators.js MUTATORS`, thresholds `ctx.content.mutators[i].stars`).
   - *Where*: the rules tablet of Quick Battle (Advanced) and Survival setup. Not offered in campaign missions, puzzles or the Daily (their rules are fixed, stars must stay comparable).
   - *Chips*: icon + name, `aria-pressed`; a mutator is **locked** while the total campaign stars are below its `stars` threshold: lock icon, tooltip = the chip's `locked` hint (`humor/mutators_text.js`) plus "Unlocked by earning N campaign stars.", and a tap plays the error cue plus a toast with the star sentence. The nine shipped: Big Heads, Tiny Titans, Moon Gravity (knockback x3), Chicken Rain, Wine Rain Always, Friendly Fire Fiesta, Speedy Soldiers, Ragdoll Frenzy, Glass Cannons; the label is `short`, the tooltip of an unlocked chip is its one-line `desc` (both from `humor/mutators_text.js`). Several may be combined; a "Clear all" ghost button appears when at least one is on, and the setup summary line lists them.
   - *In battle*: the `mutators` HUD strip under the objective shows one badge per active mutator (icon + name, tooltip = blurb) and hides itself when none are active. The results overlay repeats the badges. When a battle's stars push the total across a threshold, the results show "Mutator unlocked: <name>" (the names a mission lists in `rewards.unlockMutators`, world.md §6).
   - *Keyboard*: the chips form a `group` with Space/Enter toggling and Tab between chips. *Touch*: chips wrap, 44 px tall.

6. **Choreography** (Settings > Gameplay "Cinematics" toggles + battle staging; UI17).
   - *Toggles* (all default on, persisted in settings): `choreoIntro` **Battle intro** (stand-off: establishing camera shot of both lines, banners wave, Brutus's intro line during the countdown), `choreoFinish` **Victory staging** (winners cheer, losers rout or sit, 1.2 s slow-mo at 0.3x on the last kill), `choreoOrbit` **Results camera orbit** (a slow orbit behind the results tablet). The existing `cinematicStart` (default off) is the separate "Start battles in the Cinematic camera" toggle.
   - *Reduce Motion* forces the reduced variants whatever the toggles say: a static establishing frame (no dolly), no slow-mo, no orbit, held cheer poses.
   - *Never blocks input*: during the intro a **Skip** chip shows and Space, Enter, click or tap skip it; Esc still opens the pause menu.
   - *Kill-cam* (Results `K`): a 4 s cinematic follow of the last hero, boss or streak kill in real-time slow-mo; K, Esc or a click exits; the button is hidden when no qualifying kill exists.
   - *Keyboard/touch*: the toggles are standard switches in the Settings tab order; touch skips the intro with a tap anywhere.

7. **Teaching beats** (HUD part `teaching`; mission 1 only, UI18).
   - *Layout*: a hint card (`role="status"`, polite live region) anchored to the HUD element it talks about, with an arrow and a pulsing ring (a `data-hud` part id or a CSS selector), the speaker's portrait, step dots, a **Got it** button for acknowledge-only steps and a permanent **Skip tutorial** button. `hud.teaching = {id, index, total, title?, text, target?, who?, canSkip?, ack?} | null`; the Game drives it and a step advances when the player does the thing, never on a timer.
   - *The five beats* (`campaign_text.js TEACHING_BEATS`, each with a speaker, a line and a plain how-to `hint` under it; the Game shows a beat at its trigger): (1) `place_spears` at `placement_start`, Plato: "Place a line of hoplites across the field..." (hint: line brush, drag across the field; target: the hoplite card and the brush row; done once >= 6 hoplites stand in a line or block); (2) `fight` at `battle_start`, Brutus: watch the line hold (hint: Space pauses, the speed keys change the pace); (3) `god_power` at `first_contact`, Cassandra: "Press 1 to call down Zeus..." (target: god-power slot 1; done on the first `god_power` event); (4) `counter` at `cavalry_brace` (first `unit_brace` or `charge_hit`), Plato: cavalry broke on the spears (hint: spears beat cavalry, archers beat spears, horses beat archers); (5) `done` at `battle_end`, Brutus: do it again for the stars (Got it).
   - *Skip*: `Game.skipTeaching()` and `settings.seenHints.teaching = true`; never shown again until Settings > Data > "Show tutorial hints again". Other modes never show it.
   - *Keyboard*: Skip is the first tab stop while a card is open; Esc is not Skip (it pauses). *Touch*: the card spans the width under its target on phones; buttons 44 px; Reduce Motion drops the ring pulse.

8. **Beacon consent** (`beacon` overlay; the owner-only diagnostics beacon of spec §14: one capped `diag/*` document per visit through the `db` capability, **opt-out** setting `beacon`, default on, scheduled T3).
   - *When*: once, on the first Title visit after the splash, and only when the `db` capability exists. Never during a battle or in an editor. **No record is written before this card has been answered**, so the player can always veto the very first one.
   - *Layout*: a modal tablet, "Help fix bugs?": what one record contains (browser and GPU name, quality tier, FPS bands, asset load paths, errors and security-policy violations), what it never contains (names, saves, battles, tracking), "Only the page's owner can read it." Buttons: **Fine by me** (keeps `beacon` on) and **Turn it off** (secondary, default focus, so the privacy-first answer is one keypress away), plus a link "Show exactly what would be sent" that expands a read-only preview built from `ctx.diag.snapshot()`. Esc or a click on the backdrop counts as **Turn it off**.
   - *State*: `settings.beacon` (bool) and `settings.seenHints.beacon` (the card has been answered). Settings > Data keeps an "Anonymous diagnostics" switch with the same state (switching it off at any time stops all further records), and the Diagnostics screen shows "Beacon: sent / off / unavailable" with the last record id. A failed send is silent and only logged in Diagnostics.
   - *Unavailable* (no `db`, e.g. a local build): the card never appears, nothing is ever sent, and the Settings row is disabled with "Not available in this build".
   - *Keyboard*: focus trap, Enter activates the focused button. *Touch*: the buttons stack at full width.

## 5. Battle HUD
- Top-centre: **army meter** (A vs B bars with unit counts, cost remaining), objective tracker, timer.
- Top-right: speed controls (0.25 / 0.5 / 1 / 2 / 4, pause), camera mode buttons (Orbit, Follow, Command, Top-down, Cinematic, Photo), kill-feed (last 5, funny verbs), settings gear.
- Bottom-left: **announcer** (portrait of Brutus/Plato/Cassandra, name, typewriter text with blips, subtitle toggle respected) + selection card (hover/selected unit: name, role, hp bar, kills, status, blurb joke).
- Bottom-centre: god-power bar (6 icons with cooldown sweep, hotkeys 1-6) and order buttons (Advance, Hold, Retreat, Focus) for the selected squad or all.
- Bottom-right: **minimap/radar** (terrain colour map + team dots + camera frustum, click to jump), type counts list (collapsible).
- In-world: unit health bars only for damaged/hovered/selected units and heroes (instanced quads), team-coloured selection ring, speech bubbles (<= 12 pooled), damage numbers (glyph quads), floating "BLOCKED!/CRIT!/BRACE!" tags, objective markers.
- Rules: DOM text updates <= 10 Hz via batched `textContent`; no layout reads in the frame loop; HUD hit areas never cover more than needed (`pointer-events:none` on containers); `Tab` hides HUD; `H`/`?` shows the controls overlay.

## 6. Input map (rebindable subset marked *) — per-context binding table; a rebinding may not collide inside its context
The defaults below are exactly `DEFAULT_KEYS` in `src/app/input.js` (KeyboardEvent `code`s; `settings.keys[action]` overrides any of them through `Input.code(action)`). Settings > Controls lists the 15 starred actions (the `ACTIONS` table of `ui/hud/_bindings.js`); the unstarred keys are fixed. Shift held = fast camera pan (x2.2). Text inputs, textareas and selects swallow keys.
| context | keys (action id) |
|---|---|
| Battle camera | W/A/S/D pan* (`pan_up/left/down/right`), Q/E rotate* (`rot_left/right`), Z/X tilt* (`tilt_up/down`), Shift fast, wheel zoom, F follow selected* (`follow`), T top-down toggle* (`topdown`), C cinematic toggle* (`cinematic`), P photo* (`photo`), M minimap (`minimap`), Tab hide HUD (`hide_hud`), H help overlay (`help`, also `?`) |
| Battle control | Space pause* (`pause`), [ ] slower/faster* (`slower`, `faster`; speeds 0.25 / 0.5 / 1 / 2 / 4), 1-6 god powers (`power_1..6`), O advance / L hold order (`order_advance`, `order_hold`; selected squad or all), Enter = Take Command on the selected unit (`command`), Esc pause menu |
| Take Command | W/A/S/D move (camera-relative, sent as tick-stamped `possess` input at 30 Hz), click/tap or J attack nearest in the aim cone, 1-3 abilities, Esc exit (god powers disabled) |
| Placement | LMB place/paint, RMB drag orbit, Ctrl/Cmd+Z undo, Ctrl/Cmd+Shift+Z or Ctrl/Cmd+Y redo, Delete erase brush (`erase`), B brush cycle (`brush`: single, line, block, scatter, erase), Q/E rotate the camera, Space focuses FIGHT and Enter confirms it, H / ? the quick tour |
| Results | R rematch (`rematch`), T tweak army (`tweak`), K kill-cam (`killcam`), Esc menu |
| Arena Builder | R rotate prop, Alt+wheel scale, Shift lower/scatter, Ctrl+Z undo, B brush cycle |
| Painter | P pencil, E eraser, G fill, L line, B box, I eyedropper, X/Y/Z mirror axes, [ ] brush size |
**Pointer, touch and focus.** Mouse: LMB select/place/paint/attack (Take Command), RMB drag orbit, MMB drag pan, wheel zoom, double-click focus unit. Touch: one-finger drag orbit, two-finger pan + pinch zoom, tap select/place, long-press = unit info, on-screen joystick + 3 buttons in Take Command; `touch-action:none; overscroll-behavior:none` on the canvas. Focus: the canvas takes keyboard focus on first pointer-down; a visible "Click the arena to give it keyboard focus" chip shows when focus is lost. Pointer lock is **optional** (only requested if the player enables "Mouse look" in Take Command; failure silently falls back to drag-look).
